cmd/8 — A/B-полёт DpVins: стоп при отпускании стика (settle_brake + pin_t)
=========================================================================

Зачем создан
------------
Полёт lv2_joy_20260906_160730 (cmd/7): скорость и линия починились, но при отпускании стика на
ходу «DpHold ведёт себя отлично, DpVins плывёт». Разбор src/lab/release_stop.py (отпускание →
гвоздь, истина Gazebo):
  ярус    |v| при отпускании  до гвоздя      путь до гвоздя  |v| при гвозде
  DpHold  4.0–4.8 м/с         1.5–2.4 с      3.3–5.0 м       0.6–1.5
  DpVins  2.7–5.4 м/с         5.1–12.4 с     6.7–16.1 м      0.3
  DpVins на виражах (dyaw 3 с +79…+124°): «ГВОЗДЬ НЕ ВЗЯТ» — пилот брал стик через 8–11 с,
  станция так и не встала (|v| не упала ниже pin_v 0.3 под ветром).
У демпфера гвоздь при отпускании тоже не ставится сразу: фаза SETTLING (цель 0), гвоздь по
стопу — но (а) kp 90 (τ выбега 1/(α·kp) = 1.3 с против 2.5 у DpVins kp 40), (б) порог стопа
pin_v/soft = 0.75 м/с на 5 м, (в) таймаут _POS_PIN_T 3 с — гвоздь принудительно, дальше BRAKE
×4. У DpVins: цель 0 на чистом P, порог 0.3 фиксированный, таймаута нет → на ветру гвоздя
нет никогда, станция без точки = чистый P навсегда.

Что меняет
----------
Код (vins_axes.py): DpVins.settle_brake (BS_DPVINS_SETTLE_BRAKE, дефолт 0) — пока гвоздя нет,
цель −brake·v с капом brake_vmax по обеим осям (закон BRAKE без точки: стоп там, где
отпустил, как BRAKE у LOITER; скорость гаснет → цель сама в 0 → гвоздь по стопу).
DpVins.pin_t (BS_DPVINS_PIN_T, дефолт 0) — не встал за pin_t с после отпускания → гвоздь
принудительно, дальше станция с BRAKE. Тест test_dpvins §27.
Профиль dpvins/brake5_stop.txt против brake5_line.txt: SETTLE_BRAKE 0 → 1, PIN_T 0 → 3.
Ожидание: с 5 м/с выбег в упоре 150 PWM как у DpHold (3–5 м, 2–3 с), «гвоздь не взят» — 0.
Висение и плечи — как cmd/7 (тормоз без точки действует только без гвоздя).

Как летать
----------
  bash cmd/8/8.sh
Как 160730: плечи стиком в упор со стопами по отпусканию (в обе стороны, сквозь порывы),
виражи с отпусканием на ходу, то же на DpHold для сравнения, посадка.

Чем судить
----------
  release_stop.py <RUN>       — DpVins: путь до гвоздя ≤ 6 м и ≤ 3 с с 5 м/с (как DpHold),
                                «гвоздь не взят» 0, уход за 5 с после гвоздя ≤ 1.5 м
  stick_lateral.py <RUN>      — плечи как cmd/7: vfwd ≥ 4.2, vlat_rms ≤ 0.7
  brake_phase.py --no-trans   — при торможении set/set, потом hold/hold; висение как cmd/6
Провал: рывок/откат при стопе (перелёт точки > 1 м, качание) → BS_DPVINS_POS_BRAKE 3 на
время торможения; гвоздь по таймауту на 1+ м/с с последующим BRAKE-перелётом → pin_t 5.

Кандидат для cmd/9 — kp на лаге twist
--------------------------------------
Вопрос пилота: «kp на лаге twist — этого в DpHold нет? на IPM такого механизма нет, да?»
Ответ: это не механизм, портировать нечего — та же ручка внутреннего контура, которая у
демпфера уже стоит на большем значении. Внутренний контур у обоих одинаковый: ошибка скорости
× kp → PWM наклона. DpHold: kp 90 PWM на единицу канала IPM; единица канала на 5 м ≈ 0.85 м/с →
≈ 76 PWM на м/с. DpVins: 40 вперёд / 32 вбок PWM на м/с — вдвое меньше. Отсюда весь остаток
разницы: разгон через гвоздь 1.2 м/с против 0.7 и возврат на тримe-излишке с той же скоростью.
Стенд при лаге twist (τ 0.11) подтверждает: kp режет СКОРОСТЬ, не пик — kp 32 → 90 даёт vmax
1.40 → 0.76, пик 2.33 → 2.27.
Почему kp у DpVins низкий: опускали с 80 до 40 из-за предельного цикла по углу с контуром
ориентации FCU (период ~1.6 с) — запас по фазе съедал лаг петли ~0.9 с, самая большая его
часть (0.35 с) была конечная разность позы; twist убрал 0.24 с. «kp на лаге twist» = вернуть kp
ближе к уровню демпфера, не поймав тот цикл. У демпфера на IPM ничего такого нет, потому что
не было проблемы: канал IPM с лагом 0.4 с и окном 0.3, kp 90 устоялся полётами — свой набор
гейнов на свой датчик.
Кандидат: dpvins/brake5_kp.txt = brake5_stop + BS_DPVINS_KP_FWD 40 → 60, BS_DPVINS_KP_LAT
32 → 48 (шаг ×1.5). Стенд τ 0.11, kp 60: пик 2.49 / остаток 0.01 / vmax 0.86.
Судить: (1) висение под порывами — gust_hold_compare (pk ≤ 3, rs ≤ 0.5, vmax ниже cmd/6
1.35); (2) разгон через гвоздь и перелёт — brake_phase.py (e(max) < 2.0, перелёт < 2.0,
v при входе в BRAKE < 1.0); (3) σθ на висении — предельный цикл стенд не видит: σθ > 1° или
дрожь наклона T ~1.6 с → откат к 50/40. Второй шаг до 90/72 — только после чистого первого.
