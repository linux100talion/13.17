# Debug-HUD в FPV (OpenHD) — что нарисовано на экране

Оверлей, который пилот видит в даунлинке OpenHD (`udp :5600`, `make fpv`), и он же
— в архивном `scene_hud.mp4`. Один и тот же код рисует оба:

| Где | Кто рисует | Кадр |
|---|---|---|
| живой FPV `:5600` | нода `openhd_streamer` (`nav_pkg/openhd_streamer.py`) | `/image_color`, полный 1280×720 → downscale 640×360 |
| архив `scene_hud.mp4` | `src/lab/hud_video.py` (пост-рендер из bag, **без ROS-графа**) | `/image_color` из `scene_bag`, ширина ≤ `SCENE_MAXW` (1280) |

Сама отрисовка — **`nav_pkg/hud_renderer.py`** (класс `HudRenderer`, без ROS-импортов).
`openhd_streamer` кормит его из колбэков ноды, `hud_video.py` — сообщениями из bag.
Картинка совпадает пиксельно: расхождение «что видел пилот» / «что показывает разбор»
было бы враньём разбора.

В `scene.mp4` HUD **нет по построению** — это чистый `/image_color` (вход нейросетей
и анализа сцены, оверлей там был бы порчей данных).

Ручки ноды: `hud` (default `true`) — весь HUD целиком; `hud_features` (default `true`) —
зелёные точки фич. `hud:=false` возвращает старое поведение: одинокий жёлтый баннер
`scene:` в левом верхнем углу.

## 1. Геометрия и палитра

Всё задано для эталонного кадра **1280×720** и масштабируется коэффициентом
`k = width / 1280` — на любом разрешении HUD занимает ту же долю кадра, что в
FPV-даунлинке (в 640×360 он вдвое мельче в пикселях, но тот же по виду).
⚠️ `width` — ширина кадра, **на котором рисуют**: стример с 2026-08-30 рисует HUD
**после** ужатия до `out_width×out_height` (640×360 → `k = 0.5`, текст растрируется
нативно, без размытия ресайзом; рамки NN1 — по-прежнему на полном кадре до ужатия),
`hud_video.py` — после даунскейла до `SCENE_MAXW` (профиль `RES=960x540` → `k = 0.75`).
Поэтому в FPV глифы объективно мельче, чем в `scene_hud.mp4`, — это разные
разрешения носителей, а не разный HUD.

- **общий коэффициент шрифта `FONT_K = 0.7`** (`hud_renderer.py`; просьба
  2026-08-30 «на ~30 % мельче»): умножает глифы, толщину, подложку, межстрочный
  шаг и первую базовую линию всех строк разом — пропорции строк между собой не
  меняются; `1.0` вернёт прежний размер. Ниже размеры даны ДО этого множителя;
- три зоны: левая стопка `x = 10·k`, правая стопка — якорь по правому краю
  (`x = w − tw − 10·k`), низ по центру (`ALT`, отступ `14·k` от нижнего края);
  первая базовая линия стопок `y = 34·k·FONT_K`, шаг строки — по высоте текста +
  `18·k·FONT_K`;
- размер шрифта: баннеры `1.0·k`, обычные строки `0.8·k`, строки ярусов `0.7·k`
  (всё ×`FONT_K`);
- каждая строка лежит на **чёрной подложке** (читаемость поверх любой сцены);
  **баннеры** заливаются подложкой ЦВЕТА СОСТОЯНИЯ, текст на них чёрный.

| Цвет | BGR | Смысл |
|---|---|---|
| зелёный | `(60,200,60)` | норма / готово |
| жёлтый | `(0,210,240)` | ждём / подозрение |
| красный | `(50,50,230)` | нет данных / отказ |
| белый | `(235,235,235)` | численная телеметрия без оценки |
| циан | `(0,255,255)` | семантика NN2 |

## 2. Порядок строк сверху вниз

Строки рисуются стопкой; отсутствующий источник **не оставляет пустого места** —
следующая строка поднимается вверх. Поэтому «строки нет» = «источника нет»
(честная деградация: на Orin без лётной ноды нет баннеров, в старом bag без
`/feature` нет `FEAT`).

```
  [зелёные точки фич — ПОД текстом, по всему кадру]
  [зелёные рамки NN1 + подпись класса — тоже под текстом]

  ┌──────────────────────────────────────────┐          IPM OK  95%   ← 5. канал вида сверху
  │ ARMED / EKF READY / EKF WARMUP           │ ← 1.  ODO 10.0Hz  0.1s    ← 7. живость VINS
  ├──────────────────────────────────────────┤          FEAT 148          ← 8. фичи трекера
  │ TIER 1 VINSHOLD                          │ ← 2.  CMD R+012 P-045     ← 9. PWM от стека
  └──────────────────────────────────────────┘
      0 DAMPER   OK                    ← 6a. ярус 0                        (правая стопка —
      1 VINSHOLD OK odom 320 ALT_HOLD  ← 6b. ярус 1: хвост = режим FCU      якорь по правому
    > 2 LOITER   WAIT ground 0.3<0.5m  ← 6c. ярус 2; «>» = его ждут          краю, сверху вниз)
    DRIFT 0.42m (37s)                  ← 10. поправка NN1
    scene: hangar_west                 ← 11. метка NN2

                 ALT baro 1.4m  ekf 1.1m  perc 1.2m       ← 4. высота ТРЕМЯ источниками —
                 (центр нижнего края кадра, отступ 14 px)     ЯКОРЬ ПО ЦЕНТРУ НИЗА
```

Три зоны (раскладка 2026-08-30): **ЛЕВАЯ стопка — режимы** (1, 2, 6a–6c, 10,
11: баннер — «какой ярус», блок под ним — «почему не выше», между ними ничего не
вклинивается); **ПРАВАЯ стопка — датчики и каналы**, якорь по правому краю сверху
вниз в порядке `IPM → ODO → FEAT → CMD` (5, 7, 8, 9); **низ по центру —
высота** (4); **правый нижний угол — компас ветра** (3.13, с 2026-09-04:
стрелка «куда дует» из трима активного стабилизатора, часть блока статуса —
тухнет с ним). Номера разделов 3.x исторические и порядок на экране не задают. Строки 1, 2, 4, 5 и 6a–6c — это ОДИН блок
из `/mission/status`: если статус протух (>3 с), исчезают все сразу (включая нижнюю
`ALT`) — в левой стопке остаются только `DRIFT` и `scene`, которые от статуса не
зависят (с 2026-08-31 строки режима FCU над ярусами нет, оживлять блок из
`/mavros/state` больше нечем). Строка 4 (`ALT`) — единственная НЕ в левой стопке: она заякорена по
центру нижнего края кадра (как приборная лента высоты, отдельно от режимов), и её
отсутствие место в стопке не освобождает — там его и не было.

⚠️ **Живость VINS и режимы — РАЗНЫЕ строки.** Жив ли VINS — только `ODO` (7): это
собственный замер стримера по `/odometry`. Баннер 2 и блок ярусов 6a–6c говорят про **лесенку
режимов**: баннер — ЧТО держит борт сейчас (имя яруса + цвет), блок ярусов — ПОЧЕМУ не
выше (гейт каждого яруса с прогрессом). Раньше баннер 2 назывался
`VINS READY / VINS WAIT (why)` и описывал гейт ОДНОГО яруса (LOITER) именем VINS —
разбор `ab_noise` (2026-08-30): на 35–58 с VINS шёл 10 Гц, а баннер писал
`VINS WAIT (extnav)`, потом `(ground)`. Ждал не VINS, а очередь зрелости и высота.

## 3. Поля по одному

> Раздела **3.3** (`res 0.07  rat 1.02`, диагностика детектора зрелости VINS)
> больше нет: строку убрали с экрана 2026-08-31 — пилоту в полёте она не нужна,
> а разбору хватает полей `res=`/`rat=` в `/mission/status` (§5) и логики в
> `control_pkg/application/ripeness.py`. Номера остальных разделов не сдвигались.

### 3.1 Баннер статуса борта — `ARMED` / `EKF READY - TAKEOFF OK` / `EKF WARMUP`

**Источник:** поле `ekf=` строки `/mission/status` + `/mavros/state` (для `ARMED`).
**Зачем:** до взлёта VINS мёртв по построению (монокуляру нужен параллакс), и баннер
гейта ниже всегда красный — пилоту нужен собственный сигнал «борт готов, можно
взлетать».

| Что видно | Цвет | Условие | Что значит |
|---|---|---|---|
| `ARMED` | зелёный | `/mavros/state` свежее 5 с и `armed=true` | борт в воздухе/на моторах |
| `EKF READY - TAKEOFF OK` | зелёный | `ekf=1`, не armed | EKF держит позицию — арм пройдёт |
| `EKF WARMUP` | жёлтый | `ekf=0`, не armed | EKF ещё греется, арм упрётся в `WaitEkfPos` |
| (баннера нет) | — | в статусе нет поля `ekf=` | старый bag — честная деградация |

Машина состояний: `EKF WARMUP` → `EKF READY` → (арм) `ARMED` → (дизарм) снова
`READY`/`WARMUP` по текущему `ekf=`.

**`ekf=1` считается ровно тем же критерием, каким `WaitEkfPos` (`step.py`) пускает
арм:** свежий `/mavros/local_position/pose` (окно `EKF_FRESH_SEC = 2.0` с).
⚠️ **В полёте показывается `ARMED`, а не `ekf`** — намеренно: после GPS-kill
`local_position` замолкает штатно, и `WARMUP` в воздухе врал бы.

### 3.2 Баннер яруса — `TIER n NAME` (только имя яруса и цвет)

**Источник:** `tier=`, `lvl=`, `sw=` и гейты ярусов строки `/mission/status`
(лётная нода `bootstrap_arch2`; логика — `control_pkg/application/hud.py`, офлайн-тест
`src/control/test/test_hud_status.py`; активный ярус — правда самого шага
`Freefly.ladder_state()`, не пересчёт: гистерезисы ярусов живут в `_ladder_tier` /
`_mode_target`).

**Что отвечает:** «на каком ярусе лесенки SF-мастера борт СЕЙЧАС» — одно слово и
цвет, читаемые боковым зрением. Пилот в схеме SF-мастер не «щёлкает в LOITER» — SC
задаёт потолок, лесенка сама лезет на лучший готовый ярус (`docker/sim/LV2_loiter.md`,
`sf-master-ladder`). Ярусы: **0 DAMPER** (IPM-демпферы) → **1 VINSHOLD** (наш стек на
VINS) → **2 LOITER** (штатный, позицию держит FCU по EKF-от-VINS).
**Всё остальное — почему лесенка не выше, латч LOITER, MANUAL — намеренно НЕ здесь**,
а в блоке ярусов 3.6 (там оно есть по построению; в баннере дублировалось бы).

| Текст | Цвет | Что значит |
|---|---|---|
| `TIER 2 LOITER` / `TIER 1 VINSHOLD` / `TIER 0 DAMPER` | зелёный | ярус = потолок SC и его гейт открыт: лесенка на месте, выше пилот не просил |
| то же | жёлтый | лесенка НИЖЕ потолка — ждёт следующий ярус (в 3.6 он помечен `>`, там и причина с прогрессом); либо ярус = потолок, но его гейт мигает (гистерезис 3×fresh держит) |
| то же | красный | следующий ярус мёртв (VINS нет / протух > 3×fresh) или FCU не подтверждает LOITER дольше 5 с (`FCU REFUSES` в 3.6) |
| то же | белый | `sw=1` — MANUAL (SF не-вверх): пилот на сырых стиках, лесенка борт не ведёт; ярус — что держало бы без перехвата (маркера `>` в блоке 3.6 при этом нет) |
| `LOITER READY` / `LOITER WAIT (why)` / `NO VINS (why)` | зел/жёлт/крас | **без лесенки** (старый bag, легаси-селектор `BS_SF_MASTER=0`, миссия с `loiter<t>`): голый гейт яруса 2 по `st/why` — прежний баннер под честным именем; блока 3.6 там нет, поэтому причина остаётся в баннере |
| `LANDING FCU POS` / `LANDING DAMPER` / `LANDING VINSHOLD` / `LANDING TOUCHDOWN` | зел / жёлт / жёлт / зел | **мягкая посадка по кнопке SA** (`land=` в статусе, шаг `SoftLand` после `Freefly`; `config.ff_land`): `FCU POS` — режим LAND, позицию держит EKF-от-VINS (борт был в LOITER, стек пуст); `DAMPER`/`VINSHOLD` — снижение в ALT_HOLD под нашим стеком (стик = наклон; так садимся «сразу, до VINS»); `TOUCHDOWN` — касание, газ в пол, ждём дизарм. Поверх баннера яруса: пока идёт посадка, лесенка не ведёт |

Мотив появления прежнего баннера — полёт `lv1_joy_20260822_232043`: LOITER не
залатчился, потому что VINS инициализировался только ПОСЛЕ посадки; пилот щёлкал CH6
вслепую, гейт молча держал. Мотив переделки — `ab_noise` (2026-08-30), см. §2.

**Нет свежего `/mission/status` (>3 с) — баннера нет вовсе.** Так выглядит голый
стример на Orin без лётной ноды: остальные строки живут, баннеров нет.

### 3.4 `ALT baro 1.4m ekf 1.1m perc 1.2m` — высота ТРЕМЯ источниками

**Источник:** поля `alt=`, `zekf=` и `palt=` статуса.
**Место:** единственная строка НЕ в левой стопке — **заякорена по центру нижнего
края кадра** (отступ 14 px @1280, масштабируется с `k`): высота читается как
приборная лента, отдельно от режимов (просьба 2026-08-30). Тухнет вместе со всем
блоком `/mission/status` (>3 с).

- **`baro`** — `rel_alt` снапшота миссии, то есть высота, которой живут гейты миссии.
  При `BS_ALT_SRC=baro` (профиль LV) это сырой барометр — независим от EKF и не
  замерзает без GPS. При `alt_src=global` — `/mavros/global_position/rel_alt`.
- **`ekf`** — `z` из `/mavros/local_position/pose`, «высота глазами EKF3» (fusion
  баро+vision) — того самого сообщения, чьей свежестью считается `ekf=`.
- **`perc`** — **высота ПЕРЦЕПЦИИ** (`RosPerception._alt`: ручка `perc_alt_src` +
  латч нуля `perc_alt_zero`). **Именно по ней судит гейт земли канала вида сверху** —
  ни `baro`, ни `ekf` к этому решению отношения не имеют. Появилась потому, что
  разбор прогона `183305` упёрся ровно в это: HUD показывал две первые высоты, а
  канал закрывала третья.

| Цвет строки | Условие | Диагноз |
|---|---|---|
| белый | расхождение в пределах порога | вертикали согласованы |
| **жёлтый** | `abs(baro − perc) > max(0.2, 0.2·baro)` (без `palt` — по `ekf`) | **высота, по которой судит гейт, разошлась с миссией** |
| `ekf --` / `perc --` (белым) | источник протух (после GPS-kill) или старый bag | честное «нет данных», а не последнее значение |

⚠️ **Порог относительный, а не 0.5 м как раньше.** Фиксированные полметра на низком
полёте бесполезны: в `183305` расхождение было 0.3 м — это 100% высоты полёта — и
строка оставалась белой. Теперь при `baro` 0.3 м порог 0.2 м, и та же строка горит
жёлтым.

**Почему это важно у земли:** масштаб канала вида сверху (IPM) ∝ высоте, и демпфер
слепнет первым. Прогон `174603`: EKF z был −0.27 м к истине → гейт `alt<0.5` душил
демпфер на истинных 0.7 м. Прогоны `183305`/`185921` довели это до предела: смещение
EKF-z (−0.27 и −0.21 м) превысило всю высоту полёта (0.26–0.27 м), гейт не открылся
ни разу, демпфер выдал 0 PWM, борт унесло на 54 и 40 м. Лечится латчем нуля высоты
перцепции по арму (`perc_alt_zero`, дефолт вкл) — тогда `perc` показывает настоящую
AGL и совпадает с `baro`.

### 3.5 `IPM OK 95%` — канал вида сверху (то, на чём стоит демпфер)

**Место:** правая стопка, 1-я строка (верхний правый угол).

**Источник:** поля `ipm=` (это `s.ipm_ok` — «скоростям можно верить») и `ipmf=`
(`s.ipm_fail` — причина брака КАДРА) статуса. Процент — доля кадров с `ipm=1` за
скользящее окно **3 с** (считает сам рендерер).

Зачем и процент, и код: у земли гейт дребезжит, и по одному кадру «10% годных»
неотличимы от нуля (`185921` — ровно этот случай).

| Что видно | Цвет | Условие | Что значит |
|---|---|---|---|
| `IPM OK 95%` | зелёный | `ipm=1`, `ipmf=0` | кадр выпрямился, поток посчитан — оси видят |
| `IPM FEW LK 88%` | жёлтый | `ipm=1`, `ipmf≠0` | кадр брак, но фильтр `ipm_vel_tau` мостит провал — скорости ещё живы |
| `IPM ALT GATE 0%` | красный | `ipm=0` | **оси слепы**: `DpRollRate`/`DpPitchRate` замерзают, PWM гаснет к 2×stale |

Коды `ipmf` (та же таблица, что `FlowEstimator.ipm_fail`; подписи ASCII — Hershey-шрифт
OpenCV не рисует кириллицу):

| код | на экране | причина |
|---|---|---|
| 0 | `OK` | кадр годен |
| 1 | `ALT GATE` | **гейт земли**: высота перцепции ниже `_ALT_GROUND` (0.08 м при включённом `ipm_alt_floor`, иначе 0.5) |
| 2 | `NO WINDOW` | окно полосы не видно (горизонт) |
| 3 | `WARP OOB` | варп ушёл за кадр |
| 4 | `FEW PTS` | мало фич в полосе (<20) |
| 5 | `FEW LK` | мало выживших LK (<15) |
| 6 | `OFF` | канал выключен ручкой |
| 7 | `NO REF` | нет опорного кадра (хвост любого сброса) |

`IPM ALT GATE` красным при живой картинке = «демпфер молчит не потому, что не видит,
а потому, что ему запретили по высоте» — смотреть на `perc` в строке выше.

### 3.6 Блок ярусов — лесенка SF-мастера

Шапки `<MODE> ARM  SC 2  TIER 1` над блоком **больше нет** (просьба 2026-08-31):
потолок SC и активный ярус читались дублем — активный ярус виден по заливке
строки, куда лезет лесенка — по маркеру `>`, armed — по баннеру статуса борта
(3.1). **Имя режима FCU уехало в хвост строки активного яруса** (`msg.mode` из
`/mavros/state`, только имя, без `ARM/DISARM`; протух за 5 с или нет
`mavros_msgs` в образе — хвоста нет, строка как была).

Вместе с шапкой с экрана ушли две вещи, которых больше нигде нет:
**`MANUAL (SF)`** (`sw=1` — но баннер яруса при этом белый, см. 3.2, и маркера
`>` в блоке нет) и **`SA LAND`** (`sa=1` без баннера `LANDING` = гейт «низко и
стоим» не пустил: `rel_alt ≤ BS_LAND_ALT_MAX` 5 м, `|v| ≤ BS_LAND_V_MAX` 1 м/с —
причина в логе ноды, `SA: гейт закрыт`).

**Блок ярусов** (мелко, только при `tier=` в свежем — <3 с — статусе, т.е. при
живой лесенке SF-мастера в шаге `Freefly`; нет лесенки — строк нет вовсе,
`/mavros/state` этот блок больше не оживляет):

```
   0 DAMPER    OK                        ← канал вида сверху: ipm=1
   1 VINSHOLD  OK odom 320  ALT_HOLD     ← гейт VinsHold: t1=READY; активный ярус
                                            (заливка) + хвост = режим FCU
 > 2 LOITER    WAIT ground 0.3<0.5m      ← гейт штатного LOITER: st=WAIT why=ground
```

**Маркер `>`** — ярус, на который лесенка ПЫТАЕТСЯ подняться (следующий над
активным, пока активный ниже потолка SC и пилот не в MANUAL). Его текст и есть ответ
«почему не выше» — то, что раньше дублировалось в баннере 3.2. Нет `>` — лесенка на
месте (ярус = потолок, либо MANUAL).

**Активный ярус** — строка с заливкой (`tier=`), и она же несёт **режим FCU** в
хвосте; **потолок SC** (`lvl=`) виден по белым строкам выше него («пилот не
просил»). Это и есть то, что писала шапка.

⚠️ Хвост с режимом живёт на `/mavros/state` (5 с), а сама строка — на
`/mission/status` (3 с): пропал режим при живых ярусах = замолчал MAVROS, не
лесенка.

| Ярус | Гейт (единый источник правды) | Тексты |
|---|---|---|
| `0 DAMPER` | канал вида сверху `ipm=`/`ipmf=` (тот же, что строка 3.5) | `OK`; `BLIND <код>` (`ALT GATE`, `FEW PTS`, … — таблица в 3.5) |
| `1 VINSHOLD` | `t1=`/`w1=` — **зеркало `VinsHandover.vins_ready`**: `odom ≥ vins_min` (`vmin=`, `BS_VINS_MIN`, в LV-профилях 300) и возраст одометрии `< vins_fresh_sec`; вниз — гистерезис 3×fresh (`Freefly._ladder_tier`) | `OK odom 320`; `WAIT odom 250/300`; `WAIT stale 2.3s`; `NO VINS`; `NO VINS stale 7.0s` |
| `2 LOITER` | `st=`/`why=` — **те же условия, которыми `Freefly._mode_target` и `LoiterHold` пускают LOITER**: `extnav_ready` + свежий VINS + `rel_alt > loiter_alt` (`lalt=`, `BS_LOITER_ALT`, 0.5 м); плюс латч `lat=` | `OK`; `WAIT extnav 250/300 28/30s` (счётчик к `rcnt=` и секунды потока к `rsec=` — оба порога очереди `EK3_SRC1_*`, см. ниже); `WAIT ground 0.3<0.5m`; `WAIT stale 2.3s`; `LATCH 3s`; `FCU REFUSES 7s`; `NO VINS …` |

Цвета строк: **активный ярус — заливка** цветом его гейта (зелёная — держит;
жёлтая — держит на гистерезисе); ниже потолка и готов — зелёный текст; закрыт —
жёлтый с причиной; мёртв — красный; **выше потолка SC — белый** (пилот не просил,
готовность показывается, но не выбирается).

**Про `WAIT extnav`.** В LV=2 EKF с земли живёт на нулевой позе моста; очередь ноды
переписывает `EK3_SRC1_POSXY=6` (и тем открывает `extnav_ready`) **по зрелости
VINS**: `ripe_sec` (30 с) от первой одометрии **и** `odom > vins_min` (300), либо
раньше — по детектору зрелости (`ripeness.py`, поля `res=`/`rat=` статуса — на
экране их нет, см. §5), но не раньше 8 с / 80 одометрий. Пока это не
случилось, VINS может быть идеально жив (`ODO` зелёный) — карантин осознанный:
свап на незрелый VINS давал разгон-улёт (полёт 2026-08-20 №3).

**Про `WAIT ground`.** `rel_alt` (баро при `BS_ALT_SRC=baro`, LV=2) ≤ `loiter_alt`
0.5 м: висение в 30–40 см от земли LOITER не получит по построению (0.5 = выше
шума баро ~0.3 и детектора посадки). Это свойство гейта, не проблема VINS.

Порядок проверок гейтов фиксирован (первое сработавшее и печатается):
`no_odom` → `stale(DEAD)` → `extnav` | `odom` → `stale(WAIT)` → `ground` → `READY`.

### 3.7 `ODO 10.0Hz  0.1s` — живость одометрии VINS

**Место:** правая стопка, 2-я строка (после `IPM`).

**Источник:** сам стример меряет приходы `/odometry` (одометрия `vins_estimator`).
Это **собственная** оценка стримера, независимая от лётной ноды: топик публикуется
только после успешного init → **зелёный ODO = «VINS инициализировался и жив»**.

- **Гц** — по скользящему окну **3 с** (кольцо на 64 прихода);
- **с** — возраст последнего сообщения.

| Что видно | Цвет | Условие |
|---|---|---|
| `ODO 10.0Hz  0.1s` | зелёный | возраст < 0.5 с |
| `ODO  9.8Hz  0.9s` | жёлтый | 0.5…1.5 с |
| `ODO  0.0Hz  4.2s` | красный | > 1.5 с — поток встал |
| **`ODO --`** | красный | сообщений не было **ни одного** — VINS без init |

`ODO --` до взлёта — норма (нет параллакса). `ODO --` в воздухе — ЧП.

### 3.8 `FEAT 148` — фичи VINS-трекера + зелёные точки

**Место:** правая стопка, 3-я строка — СРАЗУ под `ODO` (с 2026-08-31: пара
«жив ли VINS (`ODO`) / за что он цепляется (`FEAT`)» читается вместе).

**Источник:** `PointCloud` от `feature_tracker`. Подписка на **оба** имени сразу
(`/feature` — ремап в симуляции, `/feature_tracker/feature` — на борту), издатель
всегда ровно один.

- **`FEAT n`** (белым) — сколько точек трекер отдал в последнем сообщении.
  Это то, за что реально цепляется одометрия.
- **`FEAT --`** (красным) — сообщений нет дольше **3 с**. Замолк при живой камере — ЧП.
- **Зелёные точки** на кадре — сами фичи в пикселях `u,v` (каналы PointCloud
  `[id, u, v, vx, vy]`). Рисуются **под** текстовым блоком, чтобы не портить строки;
  радиус `max(2, 3·k)`.
  - **Точки тухнут раньше счётчика — за 0.5 с**: `/feature` идёт ~10 Гц против ~30 у
    камеры, точки «залипают» на 2–3 кадра, а протухшие ВРУТ быстрее, чем счётчик.
  - Выключаются параметром `hud_features:=false` (в пост-рендере — `SCENE_FEAT_DOTS=0`),
    тогда остаётся только счётчик.
  - В `hud_video.py` координаты домножаются на коэффициент даунскейла `SCENE_MAXW`;
    в живом стримере оверлей рисуется на полном кадре ДО resize → 1:1.

Пустая земля под бортом (мир `mili_fortress` ближе ~3 м бесфактурен) видна тут
мгновенно: точки уходят с нижней части кадра, `FEAT` проседает.

### 3.9 `CMD R+012 P-045` — PWM-смещения от стека

**Место:** правая стопка, 4-я (последняя) строка.

**Источник:** `/flow_dbg.vector.x` (крен) и `/flow_dbg2.vector.x` (тангаж) —
`rc.roll − 1500` и `rc.pitch − 1500`, то есть **что стек добавил к стикам**
(`RC_CENTER = 1500`). Белым, формат `%+04.0f`.

- `R` — крен: знак = сторона сноса, который демпфер парирует;
- `P` — тангаж: минус = нос вниз = вперёд;
- `R+000 P+000` при живом демпфере = стек ничего не даёт (слеп либо гейт закрыт);
- **тухнет за 2 с** — строки нет, если лётная нода не публикует `/flow_dbg*`.

Полная картина осей (достоверность, IPM в метрах, коды брака) в HUD НЕ выводится —
она в bag: `/flow_dbg` `.y/.z` = боковой поток/conf, `/flow_dbg2` `.y/.z` =
продольный/визуальный yaw, `/flow_dbg8/9` = канал вида сверху в м и м/с, где
`z` — **код причины брака кадра** (`ipm_dbg_z`). Разбирается скриптами `src/lab/`.

### 3.10 `DRIFT 0.42m (37s)` — поправка NN1

**Источник:** `/nn1/drift` (`Vector3Stamped`) от `ray_tracer` — трансляция
`FrameAnchor.t`, то есть смещение, которым засечка по ориентиру правит мир VINS.
На экране — **норма вектора в метрах**. Белым.

- Засечки редкие, поэтому строка **не тухнет никогда** — вместо этого при возрасте
  **> 10 с** к ней дописывается `(Ns)`: «поправка старая, столько секунд назад».
- Строки нет, если `/nn1/drift` не приходил ни разу (NN1 не запущена — штатно на Orin
  и в большинстве прогонов сима).
- Растущий `DRIFT` = VINS уходит от абсолютной привязки; это ровно тот дрейф, ради
  сброса которого существует Нейросеть №1.

### 3.11 `scene: hangar_west` — метка NN2

**Источник:** `/nn2/scene` (`std_msgs/String`) от `nn2_scene` — ближайшее место в
топологической карте облёта (DINOv2 + FAISS). Цвет **циан**.
Не тухнет (последняя метка залипает); строки нет, пока NN2 не сказала ни слова.

### 3.12 Рамки NN1 (не строка HUD)

Зелёные прямоугольники + подпись `class_id` — детекции `/nn1/detections`
(`vision_msgs/Detection2DArray`) от `nn1_anchor`. Рисуются в координатах **полного**
кадра до resize, поэтому масштабировать боксы вручную не нужно.

⚠️ **Рамки не имеют таймаута** (в отличие от всех строк HUD): кэш
`last_detections` держит последнее сообщение до следующего. Для FPV «залипание»
нормально (NN1 ~1 Гц), но при упавшей NN1 рамки останутся на экране навсегда.

### 3.13 `WIND 11.3 IPM` + компас — стрелка ветра, источник по ярусу (2026-09-04)

> Принцип обоих источников, вывод формулы, знаки, проба Ф0 и границы честности
> целиком — **`src/control/windspeed.md`**. Здесь — только как поле HUD.

**Источник:** поля `wnp=`/`wnr=`/`wns=` `/mission/status` — ветер в PWM каналов,
источник ПО ЯРУСУ (нода выбирает): **ярусы 0/1 — наш ТРИМ** активного
стабилизатора (`wns=ipm` демпфер / `wns=vins` DpVins — контур держит вживую,
трим гладко следит); **ярус 2 LOITER — ветер EKF3 drag-фьюжна**
(`wns=ekf`, `/mavros/wind_estimation`), т.к. наш стек пуст и трим замёрз бы.
Правый нижний угол: круг-компас ОТНОСИТЕЛЬНО НОСА (метка сверху = нос),
стрелка — КУДА ДУЕТ, подпись — сила и источник. **Слева `V x.x`** — модуль
скорости борта активного датчика вида (`spd=`: ярус 0 IPM, ярусы 1/2 VINS).
Цвет белый.

**Формула** (общая для обоих источников, рендерер): сила `v = 10·√(PWM/100)`
(якорь 100 PWM ↔ 10 м/с, лобовое ∝ v²); направление «дует к» в теле =
`atan2(-wnr, wnp)`. Трим (0/1): наклон ПРОТИВ ветра, знак сверен полётом
`joystick/1` (дует к 98° при истине 98°, 127 PWM → 11.3 м/с). EKF (2):
`wind_from_ekf` кодирует нативную м/с в тот же PWM (`pwm=100·(v/10)²`).

**Ярус 2 = EKF3, не трим.** DpVins в LOITER не тикает → трим замерзает и порыв
НЕ ловит (прогон `191327`: застыл на 2.7 м/с сквозь два порыва 11 м/с, борт
реально кренился 9.5°). EKF3 drag-фьюжн следит: проба Ф0 — сошёлся к 10.0 @98°
= истина в висении, на VINS-external-nav без GPS. Требует `BS_EKF_DRAG>0`
(`EK3_DRAG_BCOEF`, дефолт 32) + WIND(168) в стриме (`nav_up`); иначе в LOITER
стрелки нет.

**Честность:** ветер точен на УДЕРЖАНИИ; манёвр/первые секунды — врёт (трим не
выучен; EKF-ветер дёргается, когда EKF-скорость плохая — резкое движение или
разнос VINS). Протухший статус (>3 с) гасит виджет. Тесты: `trim_pwm`/
`seed_trim` в `test_dpvins.py`, `wind_from_ekf` (знаки/масштаб) в
`test_hud_status.py`.

## 4. Контракт времени и деградация

Все `set_*` принимают `t` = **часы вызывающего**, `draw(frame, now)` меряет возрасты
в тех же часах → пороги **RTF-независимы**:

- живой стример — часы ноды: **sim-время** в симуляции, wall на Orin;
- пост-рендер — **sim-время bag**: у штампованных сообщений `header.stamp`,
  у `/mission/status` (String без header) — штамп последнего штампованного
  сообщения перед ним в порядке записи (ошибка ≤ кадра, пороги 0.5–3 с её не чувствуют).

Сводка таймаутов:

| Элемент | Таймаут | Что показывает по истечении |
|---|---|---|
| точки фич | 0.5 с | гаснут (счётчик ещё жив) |
| `/mission/status` (баннеры, `IPM`, ярусы, `ALT`) | 3 с | весь блок исчезает |
| `FEAT` | 3 с | `FEAT --` красным |
| режим FCU (хвост активного яруса) | 5 с | хвост исчезает, строка яруса остаётся |
| `CMD` | 2 с | строка исчезает |
| `ODO` | — | всегда рисуется (`ODO --` красным, если не было ни одного) |
| `DRIFT` | — | не тухнет, после 10 с показывает возраст |
| `scene:` | — | не тухнет |
| рамки NN1 | — | **не тухнут** (см. 3.12) |

**Принцип:** чего нет в источниках — того нет и на экране. Ни одна строка не
показывает «последнее известное» молча.

## 5. Поля `/mission/status`, которых на экране НЕТ

Строка публикуется целиком и пишется в bag (`TOPICS_EXTRA` в `freefly_lv.sh`), а HUD
рисует только часть. Полный формат:

```
t=84.20 st=READY why=- ekf=1 extnav=1 odom=1843 age=0.1 alt=1.4 zekf=1.1 palt=1.2 \
    ipm=1 ipmf=0 res=0.07 rat=1.02 rcr=0 rcp=-180 rct=0 rcy=0 sw=-1 \
    lalt=0.5 ripe=65.2 rsec=30 rcnt=300 lvl=2 tier=2 lat=-1.0 t1=READY w1=- vmin=300 \
    wnp=-27 wnr=57 wns=vins spd=0.31 brk=hold/brk ifz=0/0
```

| Поле | На экране | Смысл |
|---|---|---|
| `t` | **нет** | sim-время снапшота, с. Строка — `String` без header, в bag ложится по стеночному времени приёма, а RTF плывёт (ab_frame: сдвиг −2…−5 с) — выравнивать разбор по этому полю, не по времени bag |
| `st` / `why` | строка 6c, баннер 3.2 | гейт ЯРУСА 2 (штатный LOITER) — не живость VINS |
| `ekf` | баннер 3.1 | свежесть `/mavros/local_position` (< 2 с) |
| `extnav` | **нет** (косвенно — `why=extnav`) | EKF переведён на ExternalNav (очередь `EK3_SRC1_*`) |
| `lvl` / `tier` | блок 3.6, баннер 3.2 | потолок SC (0/1/2) и активный ярус лесенки (правда `Freefly.ladder_state`). Полей нет без лесенки (легаси-селектор, миссии) |
| `lat` | строка 6c | сим-секунд с момента, как LOITER выбран, а FCU режим не подтвердил; `-1.0` — не латчим |
| `t1` / `w1` / `vmin` | строка 6b | гейт яруса 1 (зеркало `VinsHandover.vins_ready`) и его порог `vins_min` |
| `lalt` | строка 6c | `loiter_alt` — порог «в воздухе» гейта LOITER |
| `ripe` / `rsec` / `rcnt` | строка 6c | сим-секунд от ПЕРВОЙ одометрии (`-1.0` — не было) и пороги зрелости очереди extnav: время потока `ripe_sec` и счётчик `ripe_min` |
| `odom` | **нет** | счётчик принятых одометрий VINS |
| `age` | **нет** | возраст последней одометрии, с (клип 999) |
| `alt` / `zekf` / `palt` | строка 3.4 | rel_alt миссии / z глазами EKF3 / высота перцепции |
| `rcr` / `rcp` / `rct` / `rcy` | **нет** | стики пилота глазами ноды: сырой PWM − 1500 (крен/тангаж/газ/рыскание). Нужны разбору bag: `/joy` штампован стеночным временем джойстик-ноды и при плавающем RTF с sim-временем не выравнивается (сдвиг «плывёт» −2…−5 с за полёт); здесь стик в одной строке и с одним штампом со всем остальным |
| `reb` | **нет** | перерождений потока VINS за полёт (наш `/restart` или переинициализация эстиматора сама; детект `VinsTrack`: дыра штампов >1 с либо скачок позы быстрее 12 м/с). Каждое обнуляет `odom=` — так в ленте видно, почему `t1` вдруг `WAIT/odom` при живом VINS (20260905_114248: четыре рестарта в воздухе) |
| `scl` | **нет** | срабатываний чека ЗАНИЖЕНИЯ \|vins_v\| против IPM за полёт (третий канал гейта здоровья, `Handover.vins_sane`): VINS видит много меньше стойко годного IPM на висении низко = масштаб схлопнулся → ярус 1 падает на демпфер на 30 с. Пишет нода (состояние гейта, не датчика). В ленте объясняет демоут яруса при свежем и «медленном» VINS |
| `sw` | **нет** | тумблер авто/ручной (`pilot_switch`): 1 = MANUAL, пилот взял управление |
| `sa` | **нет** (с 2026-08-31, ушло вместе с шапкой 3.6) | кнопка посадки пилота (`pilot_land`, уровень): 1 = нажата. Источник — `/joy` (`BS_LAND_JOY`, дефолт `b0`) или one-shot `make sa-land` |
| `land` | баннер 3.2 (`LANDING …`) | ветка мягкой посадки `SoftLand.land_state`: `pos` (LAND на EKF) / `damper` / `vinshold` (ALT_HOLD под стеком) / `touch` (касание). Поля нет, пока шаг посадки не активен |
| `sf` / `sx` / `sy` / `spx` / `spy` | **нет** | рама станции в осях курса (`StationFrame`, `BS_STATION_FRAME=yaw`): `sf=1` — рама активна, `sx/sy` — мировая позиция рамы (м, из пути IPM под курсом `att_yaw`), `spx/spy` — общий 2D-гвоздь (`--` — гвоздя нет). Полей нет вовсе, когда станция в осях борта |
| `brk` / `ifz` | **нет** (с 2026-09-06) | ФАЗА СТАНЦИИ активного стаба ярусов 0/1 по осям `тангаж/крен` (у DpVins — вперёд/вбок) и ЗАМОРОЗКА ТРИМА по осям. Коды: `rel` — стик этой оси живой (гвоздь отпущен), `set` — гвоздя нет, тормозим до стопа, `hold` — гвоздь взят, закон RETURN, `brk` — фаза BRAKE (уходим от гвоздя быстрее `brake_v`, цель −brake·v). `ifz=1` — И-член оси не учится на этом кадре (защёлка стик→гвоздь / хвост до гвоздя / брейк при `brake_t` ≥ 0 / анти-виндап в упоре). Источник — `station_phase()` того же стаба, что даёт стрелку ветра (`StationKeeper.phase` у демпфера, свои флаги у DpVins). До этого фазу BRAKE в bag было не видно, разбор cmd/3–5 шёл по косвенным признакам (скорость против гвоздя, константа `wnr`); `gust_hold_compare.py` теперь печатает секунды BRAKE за цикл порыва (`b`) и за окно (`brk_s`). Закрытие держится 5 с (латч). Полёт 142811: 687 подтяжек и отравленная ориентация EKF были видны только в sim_nav.log. Полей нет без ray_tracer |
| `ipm` / `ipmf` | строка 3.5 | живость канала вида сверху и код брака кадра |
| `res` / `rat` | **нет** (строка убрана 2026-08-31) | 2-я ступень гейта зрелости VINS (`VinsRipeness`, 1-я — время потока `ripe_sec`). `res` — EMA residual «поза против скорости» `|Δpose/Δt − twist|`, м/с: первое окно после init 0.5–0.7, после успокоения 0.05–0.10; «тихо» = ниже `quiet_res` 0.15 подряд `quiet_sec` 4 с; масштаб-ошибку, уже узаконенную окном, НЕ ловит. `rat` — вертикальный ratio `(pos.z − z0)/(ref_alt − ref0)`, тест МАСШТАБА: зрел = попадание в полосу [0.8, 1.25] `ratio_n` 3 раза подряд, оценивается после ухода референса на `ratio_min_dz` 1.5 м (полоса широкая нарочно — ловим КРАТНЫЕ ошибки, не проценты). `-1` = данных ещё нет; разрыв потока >1 с сбрасывает пару и тишину |

## 6. Как этим пользоваться

**Перед взлётом.** Ждём `EKF READY - TAKEOFF OK` (жёлтый `EKF WARMUP` = арм не
пройдёт). Баннер яруса в это время `TIER 0 DAMPER > VINSHOLD: NO VINS` (красный) —
норма, параллакса нет.

**Сразу после отрыва.** Следим за `ODO`: он должен позеленеть за 0.3–2 с после
отрыва — это init VINS. Дальше созревание видно по строке `> 2 LOITER WAIT extnav
n/N s/S` в блоке ярусов (сам детектор зрелости на экран не выведен — его `res`/`rat`
смотреть в bag, см. §5).

**Лесенка не лезет выше** (баннер яруса жёлтый/красный). Смотреть блок ярусов 3.6:
строка с `>` — ярус, которого лесенка ждёт, и что его держит. `WAIT odom 250/300` —
VinsHold ждёт счётчик, просто рано; `WAIT extnav 250/300 28/30s` — очередь зрелости (оба порога должны пройти);
`WAIT ground 0.3<0.5m` — мало высоты, поднимись выше `loiter_alt`; `WAIT stale` —
поток рвётся, лететь на нём нельзя; `FCU REFUSES` — EKF не даёт позицию (смотреть
`ALT ekf` и `DRIFT`). При всём этом `ODO` зелёный = **VINS жив, дело не в нём**.
Белый баннер яруса (и ни одного `>` в блоке) — тумблер SF не вверх (`sw=1`),
лесенка выключена, пилот на сырых стиках.

**Демпфер не держит у земли.** Первым делом — строка **`IPM`**: красный `ALT GATE` =
каналу запретили по высоте (смотреть `perc` в строке `ALT` — она и есть та высота;
жёлтая `ALT` = `perc` разошлась с `baro`, значит нужен латч нуля `perc_alt_zero`).
Красный `FEW PTS`/`FEW LK` = наоборот, зрению не за что цепляться — смотреть `FEAT`
и зелёные точки: пропали с нижней части кадра — земля бесфактурна (см.
`mili_fortress_fine`). Жёлтый `IPM` с высоким процентом = канал жив, фильтр мостит
одиночные кадры, причина не здесь.

**LOITER разносит.** `DRIFT` растёт скачками + трек уходит — смотреть якорь кадра
(`FrameAnchor`, `Δyaw`); в HUD это видно косвенно, разбор — по bag.

## HUD на борту vs OSD на земле (разбор 2026-09-04)

Вопрос: обязаны ли мы вжигать HUD в кадр на борту, или OpenHD умеет возить
данные отдельным потоком, а рисовать на земле? Ответ: **умеет оба пути**, и
они не взаимоисключающие.

**Путь 1 — вжигание на борту (наш текущий).** OpenHD безразличен к содержимому
H.264 — оверлей едет как часть картинки. Плюсы: пилот видит ровно то, что
видит борт; ноль поддержки на земле; работает с любым приёмником. Минусы:
тонкие штрихи текста и точки фич едят битрейт кодека и замыливаются на плохом
линке; чёткость ограничена 640×360 потока; на земле не переконфигурировать.

**Путь 2 — чистое видео + отдельный поток данных.** Это ШТАТНАЯ модель
OpenHD: телеметрия идёт отдельным каналом от видео (двунаправленный
MAVLink-роутинг воздух↔земля), наземный QOpenHD сам рисует OSD поверх
декодированного видео (виджеты attitude/режим/батарея настраиваются на
земле); для произвольных данных малой полосы есть транспарентный IP-туннель.
Транспорт для «HUD отдельным потоком» существует из коробки.

Две ловушки пути 2 для НАШЕГО HUD:

1. **Кастомные поля.** QOpenHD из коробки рисует стандартный FPV-OSD из
   MAVLink (режим/батарея/горизонт — это можно получить уже сейчас, MAVLink
   через OpenHD и так идёт). А лесенка ярусов, гейт LOITER, ODO/IPM, дрейф
   NN1 — это наш `/mission/status`: пришлось бы паковать в кастомные
   MAVLink-сообщения (STATUSTEXT/NAMED_VALUE_*) и писать свои виджеты
   QOpenHD, либо гнать туннелем и писать свой наземный рендерер. Отдельная
   разработка + ВТОРОЙ экземпляр логики отрисовки (сейчас она одна —
   `hud_renderer.py`, бит-в-бит с архивным `scene_hud.mp4`).

2. **Синхронизация с кадром.** Зелёные точки фич рисуются по пиксельным
   координатам КОНКРЕТНОГО кадра; отдельный поток с видео покадрово не
   синхронизирован (разные задержки) — точки поплывут. Текст переживёт,
   попиксельная графика — нет.

**Вывод.** Текущая архитектура уже даёт главный плюс раздельного пути — чистый
архив (`scene.mp4` = `/image_color` без HUD по построению, HUD только в FPV).
Переносить OSD на землю имеет смысл, только если упрёмся в битрейт/читаемость
на реальном радиолинке; тогда естественный гибрид: стандартные поля — QOpenHD
из MAVLink, наши строки — STATUSTEXT'ом, попиксельное (точки фич) — вжигаемым
по флагу `hud_features`.
