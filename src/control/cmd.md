# cmd.md — КОМАНДЫ ЗАПУСКА ПРОГОНОВ

Шпаргалка по тому, чем на самом деле снимались все серии в `tune.md`. Не описание
скриптов (оно в шапках самих скриптов), а **готовые строки запуска** и правило, какую
из них брать.

Всё запускается **с хоста**, из `/root/13.17`. Ничего не запускается руками внутри
контейнера — см. «Дисциплина».

---

## 1. Четыре слоя, и какой брать

Слои вложены: каждый следующий зовёт предыдущий. Брать надо **самый верхний, который
решает задачу** — нижние не дают того, ради чего верхние написаны.

| Слой | Скрипт | Что добавляет | Когда брать |
|---|---|---|---|
| 1 | `capture_scene.sh` | атомарный прогон: рестарт стека → полёт → bag → mp4 | почти никогда напрямую |
| 2 | `calib_run.sh` | **имя** прогона, `<NAME>_bag`, `<NAME>.env` (мета), видео на Drive под именем | разовая проверка гипотезы |
| 3 | `hover_series.sh` | **N повторов** одного конфига + потрошение бэгов | одна настройка, нужен разброс |
| 4 | `rate_gain_series.sh` | **свип одной ручки** по списку значений, серия на точку | настройка гейна |

⚠️ **Слой 2 в одиночку почти всегда бесполезен для настройки.** Разброс стенда
сопоставим с эффектом: при полностью одинаковом конфиге уход за 40 с висения выходил
7.4 и 13.3 м. Одиночный прогон годится ответить «работает ли вообще / не падает ли»,
но не «стало лучше». Правило 8 из `tune.md`: n≥3 на точку, иначе вывод формулируется
как направление, а не как победитель.

## 2. Дисциплина (нарушение = выброшенный прогон)

- **`setsid nohup … &` всегда.** Серия идёт 60–90 минут, ssh рвётся. Без `setsid`
  обрыв связи убивает серию на середине.
- **Не редактировать `src/lab/*.sh` во время прогона.** Bash дочитывает скрипт по ходу
  исполнения: правка сдвигает офсет, и миссия уходит на второй круг.
- **Не редактировать `src/control` / `src/mission` во время СЕРИИ.** Они смонтированы
  в контейнер, каждый прогон делает `fresh-start` + `colcon build` — правка попадёт в
  середину серии, и две половины окажутся разными.
- **Стек поднимать только целиком.** `calib_run.sh` сам делает `fresh-start` + `wait`.
  Ручной перезапуск отдельного процесса рассинхронизирует состояние (Gazebo жив, FCU
  перезапущен) и даёт ложные диагнозы.
- **`GDRIVE_UP=1 MP4=1`** — по умолчанию в `calib_run.sh`; видео смотрится с телефона.

## 3. Готовые строки

### Разовый именованный прогон

```bash
cd /root/13.17 && setsid nohup env NAME=A1_pitch_sign \
  BS_STAB=none BS_MISSION="climb3,mv_bkwd6,land" BS_MV_LEVEL=0.375 \
  bash src/lab/calib_run.sh > /root/run_A1.log 2>&1 < /dev/null &
```

Результат: `docker/sim/output/A1_pitch_sign_bag` + `A1_pitch_sign.env` (все `BS_*` и
`WIND_*`, с которыми снято) + видео на Drive в `13.17/calib/`.

`DRY_RUN=1` — показать, что будет запущено, стек не трогать.

### Серия из N одинаковых (база: среднее и разброс)

```bash
cd /root/13.17/docker/sim && setsid nohup env N=3 PREFIX=K1s \
  BS_STAB="DpRollHold+DpPitchHold" BS_MISSION="climb3,hover40,land" \
  bash /root/13.17/src/lab/hover_series.sh > output/K1_series.log 2>&1 < /dev/null &
```

### Свип одной ручки (основной инструмент настройки)

`KNOB_NAME` свипит **любую** ручку, не только гейн rate-оси. Реально снятый свип
интегратора крена под ветром:

```bash
cd /root/13.17/docker/sim && setsid nohup env \
  WIND_SPD=3 WIND_DIR_DEG=98 WIND_FACTOR=0.4 \
  BS_IPM_DEROT=1.0 BS_IPM_WZ_TAU=2.0 BS_ROLL_RATE_KP=30 \
  BS_MISSION="climb3,hover40,land" \
  KNOB_NAME=BS_ROLL_RATE_KI KP_LIST="0 5 15" I_START=2 N=3 \
  AXIS=roll STAB=DpHoldM PREFIX_BASE=B \
  bash /root/13.17/src/lab/rate_gain_series.sh > output/B_ki_sweep.log 2>&1 < /dev/null &
```

Имена выйдут `B2s1..3` (ki=0), `B3s1..3` (ki=5), `B4s1..3` (ki=15) — номер серии растёт
с `I_START`, номер прогона внутри серии от 1 до `N`.

⚠️ **Свипится ровно ОДНА ручка.** Всё остальное в `COMMON` внутри скрипта прибито
гвоздями. Две переменные разом — это не свип, а два несравнимых набора.

### Ветер

```
WIND_SPD=3           м/с; 0 = штиль (мир и модель не патчатся вовсе)
WIND_DIR_DEG=98      КУДА дует, в МИРОВЫХ осях (0 = вдоль +X, 90 = вдоль +Y)
WIND_FACTOR=0.4      отклик КВАДРАТИЧЕН по factor (F ≈ 4.6·factor² Н при 3 м/с)
```

Борт на висении держит курс **+8°**, отсюда две рабочие постановки:

| Куда | `WIND_DIR_DEG` | Что нагружает | Чем мерить |
|---|---|---|---|
| в нос | `8` | тангаж | `vвпер` |
| боком | `98` | крен | `vбок` |

⚠️ **Ветер задан в мировых осях, а курс за 40 с гуляет на 2–15°** — «боковой» он лишь
приблизительно. Поэтому мерить надо ось-мишень в осях борта, а не полную скорость:
прогон `V2s1` по полной скорости выглядел настроенным (1.00 м/с), а на деле держал не
ту ось (`vвпер` +0.74 против `vбок` +0.13).

⚠️ **Ветер применяется при СОЗДАНИИ контейнера** — работает только с `fresh-start`
(в `calib_run.sh` это дефолт, `FRESH=1`). На `restart-all` смена ветра молча не доедет.

⚠️ **Соседнюю ось при этом надо держать настроенной.** Иначе утечка нагрузки на неё
испортит замер оси-мишени. В свипе тангажа (`C`) крен стоял на своём победителе:
`BS_ROLL_RATE_KP=30 BS_ROLL_RATE_KI=30`.

### Миссии (`BS_MISSION`)

```
climb3,hover40,land                                   висение — база всех свипов
climb3,hover5,mv_right6,hover8,mv_left6,hover8,land   челнок вбок (R4s)
climb3,hover5,yaw_l30,hover8,yaw_r60,hover8,land      курс (Y5s)
climb3,mv_bkwd6,land                                  проверка знака оси
```

⚠️ Длина висения — **такой же предмет замера, как гейн**: уход растёт со временем сам
по себе. Менять её между сравниваемыми сериями нельзя.

## 4. Обрыв на середине: досъёмка, а не пересъёмка

Серия падает от ребута машины или нехватки диска. Прогон стоит 10 минут, серия — час,
поэтому хвост доснимается отдельным запуском. Нумерация имён при этом **не съезжает**,
и досъёмка неотличима от непрерывной серии.

```bash
SEQ_START=3 …  bash src/lab/hover_series.sh       # доснять прогоны 3..N внутри серии
I_START=2 KP_LIST="100 200" …                     # доснять точки свипа со 2-й серии
```

⚠️ **Только тем же конфигом.** Досъёмка чужим конфигом молча смешает две точки в одном
имени, и по бэгам это уже не отличить.

Порядок после ребута:

```bash
ls -d docker/sim/output/C*_bag              # что уцелело
cd docker/sim && docker compose down --remove-orphans   # снять полуживой стек
rm -f docker/sim/output/<оборванный>.env    # мета без бэга (прогон не состоялся)
# … перезапуск с I_START/SEQ_START и УКОРОЧЕННЫМ списком значений
```

`docker compose down` обязателен: после ребута часть контейнеров поднимается сама, и
следующий `fresh-start` падает с «container name already in use» (код 2).

Другие коды возврата `calib_run.sh`: **3** — `<NAME>_bag` уже есть (защита от потери
данных, переименуй старый); **4** — не прошла проверка проводки ручек.

## 5. Перед запуском: проверка проводки

```bash
BS_PITCH_RATE_KI=100 bash src/lab/check_knobs.sh    # 0 = чисто, 1 = немая ручка
```

Встроена в `calib_run.sh` и роняет прогон за две секунды. **Зачем:** ручка идёт через
три уровня (`capture_scene.sh` → `bootstrap_arch2.sh` → argparse `bootstrap_node.py`),
и раньше каждый молчал, если её там нет. Свип `B3s` из-за дыры на всех трёх уровнях
отлетел с `ki=0`: значение доехало до `.env` и меты, но не до ноды — полтора часа
стенда и правдоподобный ложный вывод «интегратор не помогает».

⚠️ **Дефолт тут не защита, а маскировка.** Прошлые кампании уцелели только потому, что
`BS_IPM_WZ_TAU` и `BS_FENCE` случайно задавались значениями, равными дефолтам.

**Сквозная проверка — одна**, и статикой не заменяется: грепнуть строку запуска ноды в
логе прогона, когда стек поднялся.

```bash
grep -o "\-\-pitch-rate-ki [0-9.]*" docker/sim/output/C_pitch_ki.log | head
docker logs p1317_simulator 2>&1 | grep -i ВЕТЕР | tail -1
```

## 6. Разбор

Все разборщики гоняются в одноразовом контейнере с **абсолютными** путями монтирования:

```bash
docker run --rm -v /root/13.17/src/lab:/lab:ro \
  -v /root/13.17/docker/sim/output:/out:ro ros:humble-ros-base bash -lc \
  'source /opt/ros/humble/setup.bash; python3 /lab/hold_quality.py /out/C1s1_bag /out/C1s2_bag'
```

| Вопрос | Скрипт | Аргументы |
|---|---|---|
| снос под ветром, установившаяся скорость по осям борта | `wind_drift.py` | **имена** (`C1s1`), без `_bag` |
| спокойствие: пик, доля времени в круге 10 м, возврат | `hold_quality.py` | пути (`/out/C1s1_bag`) |
| уход по осям и его форма | `axis_split.py` | пути |
| уход набрался на наборе высоты или на висении | `step_split.py` | пути |
| разложение выхода контура на П и Д | `pd_split.py` | пути |
| сводка по серии одинаковых прогонов | `series_check.py` | префикс серии |

⚠️ **Аргументы у разборщиков разные** (`wind_drift.py` берёт имена и сам достраивает
`/out/<имя>_bag`, остальные — готовые пути). Перепутать = «нет бэга» на живом бэге.

⚠️ **Под ветром `hold_quality.py` читать осторожно:** забор 25 м цензурирует выборку.
При `ki=0` на крене все три прогона обрубались на 19–29 с, и любая плохая настройка
даёт одинаковые «22 м». Метрика там — `vбок`/`vвпер`, не метры. Когда борт висит все
40 с и уходит меньше забора (свип `C`), метры снова честные.

## 7. Индекс кампаний

Что какой буквой снято. Точный конфиг любого прогона — в его `<NAME>.env` рядом с
бэгом (там же коммит, на котором он снят).

| Префикс | Что мерялось | Ключевое |
|---|---|---|
| `A*` | знаки осей, смещение гироскопа | `BS_STAB=none`, миссии `mv_*` |
| `D`,`E` | ранний демпфер `DpHold`, `BS_PITCH_KD` | пиксельный канал |
| `F2`,`F3` | `pitch_rate_kp` (100 / 50) | `DpHoldR` |
| `G2`,`G3` | `roll_rate_kp` (60 / 30) | `DpHoldM`, обе оси в метрах |
| `K`,`M`,`N` | `BS_PITCH_KD`, висение 40 с | `DpRollHold+DpPitchHold` |
| `P2` | лучший трёхосевой на тот момент | `DpHoldM` |
| `Q2` | `ipm_derot=0` против дефолта | |
| `R4` | челнок вбок с оракулом по тангажу | `GzPitchHold+GzYawHold+DpRollHold` |
| `T`,`U` | деротация в штиль (+1 / 0) | |
| `V`,`W` | деротация, ветер 5 м/с | |
| `X`,`Y` | деротация, ветер 3 м/с | |
| `Y2`,`Y4`,`Y5` | курс: свип `yaw_kp`, миссии `yaw_*` | `DpYawHold` |
| `Z` | база без стабилизации под ветром | `BS_STAB=none` |
| `B` | **`roll_rate_ki`** {0,5,15,30,50}, ветер 3 м/с боком | победитель 30 |
| `C` | **`pitch_rate_ki`** {0,100,200}, ветер 3 м/с в нос | |

`old_B*` — прогоны эры сломанной проводки (`ki` не доезжал). Годны только как база
`ki=0`, где поломка была безвредна.

## 8. Обслуживание

```bash
df -h /                                    # серия из 9 прогонов ест ~25 ГБ до потрошения
python3 /lab/strip_bags.py …               # выкинуть кадры, оставить телеметрию (~9 МБ)
make -C docker/sim logs                    # хвост output/*.log
make -C docker/sim status                  # что живо
pgrep -af "rate_gain_series|calib_run"     # идёт ли серия
```

`hover_series.sh` потрошит бэг **после каждого** прогона (`STRIP=1`) — иначе три бэга
по 2.6 ГБ не влезают на диск. Видео к этому моменту уже собрано и залито.
