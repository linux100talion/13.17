# КАНДИДАТ A/B — общий ветровой трим ярусов 0/1 (WindTrim, BS_WIND_TRIM=1) с тремя добавками
# после отката 0c3c82b. Всё остальное = wind/baseline.txt. Дата: 2026-09-06 (cmd/11, теперь baseline cmd/bl).
# Вопрос пилота: «почему нельзя просто расшарить два числа трима между DpHold и DpVins и на
# передаче ставить флаг „выучен“?». Можно; первая версия (17ccce8) откачена по 185004/191610
# «стрелка крутится», но улика была загрязнена: на DpHold симптом дал капкан оценки нуля ω_z
# (закрыт 56dcb15), а на DpVins — ДВА ПИСАТЕЛЯ (композит DpHold остаётся в стеке яруса 1 тенью и
# писал свой И-член в общий трим параллельно с DpVins). Добавки (control/wind_trim.py):
#  (1) владелец — пишет/наблюдает/взводит «выучен» только активный ярус, тень читает;
#  (2) снимок устойчивого hold — приёмнику отдаётся не живой трим (= ветер + смещение датчика
#      источника), а последнее значение, которое источник держал устойчиво ≥ STEADY_SEC:
#      гвоздь, фаза hold без брейка, стики в центре, трим учится, |v| < STEADY_V по своему И
#      чужому датчику; вход в ярус: устойчив сейчас → живой (wt=…/L), иначе снимок (S), снимка
#      нет → живой как есть (N = старый посев); DpVins на входе всегда «выучен»;
#  (3) стрелка ветра HUD гаснет ниже 15 PWM (8→15 линейно; ветер EKF в LOITER не гасится).
# ОЖИДАНИЕ: переключения 0↔1↔2 без сноса на входе в обе стороны, после LOITER демпфер держит
# сразу (не учит ветер заново первым брейком), стрелка ветра непрерывна по направлению между
# ярусами, при слабом ветре — гаснет, а не крутится; снос яруса 0 в висении — как на baseline
# (путь демпфера через объект бит в бит, офлайн-повтор 191610).
