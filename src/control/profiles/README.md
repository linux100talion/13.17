# Профили настроек стабилизаторов

Снимки ручек `BS_*` по ярусам лесенки — чтобы A/B-кампании шли ОТ ИМЕНОВАННОГО
эталона, а не от «того, что сейчас в .env». Каталоги = ярусы:

| каталог | ярус | что внутри |
|---|---|---|
| `dphold/` | 0 — демпфер `DpHoldM` на IPM-канале | скоростной контур rate-осей, станция, мягкость, перцепция IPM/углы, курс `DpYawHold` |
| `dpvins/` | 1 — `DpVins` (дефолт с 2026-09-03) | гейны velocity-каскада, позиционный контур, трим |
| `vinshold/` | 1 — откат на `VinsHold` | флаги eagle и гейны 2D-PID; **взаимоисключающе с `dpvins/`** — source один из двух |
| `vins/` | 1 и 2 — опора VINS, общее | хэндовер и зрелость потока, гейт здоровья (три канала), мост VINS→EKF |
| `loiter/` | 2 — штатный LOITER на EKF-от-VINS | гейты миссии, TrackHold/YawBankLimit, GPS-denied/EKF, справочно параметры SITL |

Состав `baseline.txt` по каталогам (ключей на 2026-09-05):

| каталог | ключей | содержимое |
|---|---|---|
| `dphold/` | 70 | демпфер яруса 0, без изменений |
| `dpvins/` | 18 | `BS_VINS_STAB=dpvins`, гейны velocity-каскада, позиционный контур, фаза BRAKE (выкл), трим, защёлка трима |
| `vinshold/` | 14 | откат: `BS_VINS_STAB=vinshold`, флаги eagle, гейны 2D-PID и Gz-hold |
| `vins/` | 19 | общее для ярусов на VINS: хэндовер и зрелость, три канала гейта здоровья, мост в EKF |
| `loiter/` | 15 | ярус 2, без изменений |

dpvins/ и vinshold/ взаимоисключающие, применяется один из двух. Два намеренных дубля между ними: BS_VINS_STAB с разными значениями и BS_VINS_I_LATCH=1, его читает и DpVins. Общие ручки яруса 1 вынесены в vins/, чтобы при откате на VinsHold гейт здоровья и хэндовер не потерялись и не дублировались.

Проверки. check.sh по активному стеку dphold + dpvins + vins + loiter против env прогона wind_front/20: 0 расхождений. Явный вызов с vinshold/ даёт единственное ожидаемое расхождение по BS_VINS_STAB. Все 136 ключей известны bootstrap_arch2.sh или sitl_lv_profile.py. README обновлён: таблица каталогов, порядок применения, поведение check.sh.

`baseline.txt` в каждом — ЭТАЛОН на дату в шапке (то, чем летали серии
dphold_vs_dpvins 2026-09-05). Новый кандидат — копия эталона с изменёнными
строками и говорящим именем (`vinshold/ki30.txt`), в шапке: гипотеза, что
меняется, чем доказывать.

## Формат

Файл — `KEY=VALUE` по строке, комментарии `#`, без пробелов вокруг `=`; читается
bash (`source`). Три слоя, из которых собраны значения (`# слой:` над каждым блоком):
- **env** — задаёт `src/lab/freefly_lv.sh` (дефолты профиля полёта) или
  `docker/sim/.env` (профиль бокса, эталон `env.default`): эти строки видны в
  `<RUN>.env` каждого прогона;
- **нода** — не задан ни там, ни там, работает дефолт `mission_pkg/config.py`
  (проведён в `src/lab/bootstrap_arch2.sh` → argparse ноды). В профиле такие
  ручки записаны ЯВНО тем же значением — профиль самодостаточен и переживёт смену
  дефолта в коде;
- **SITL** — параметры прошивки (`docker/sim/config/sitl-extra.parm`,
  `docker/sim/scripts/sitl_lv_profile.py`): в профиле СПРАВОЧНО, закомментированы
  (`#SITL …`), применяются не через env.

Ручки полёта вне стабилизаторов (`LV`, `BS_SF_MASTER`, `BS_MISSION`, `BS_PILOT`,
бюджеты фаз, посадка `BS_LAND_*`, `BS_FENCE`, `WIND_*`) здесь не живут — они в
`env.default`/`freefly_lv.sh` (шпаргалка `docker/sim/env.md`).

## Как применить

Приоритет `freefly_lv.sh`: env снаружи > `docker/sim/.env` > его дефолты > нода.
Профиль подаётся снаружи и перекрывает всё:

```bash
set -a
. src/control/profiles/dphold/baseline.txt
. src/control/profiles/dpvins/ki30.txt          # кандидат вместо эталона (или vinshold/… для отката)
. src/control/profiles/vins/baseline.txt
. src/control/profiles/loiter/baseline.txt
set +a
WIND_SPD=1 WIND_GUST="spd=8 at=30 rise=2 hold=5 fall=4 every=20" bash src/lab/freefly_lv.sh
```

`<RUN>.env` прогона зафиксирует применённые значения (только те, что дошли до
env; строки «нода» при совпадении с дефолтом там тоже появятся, раз заданы явно).
Проверка эталона на расхождение с живым прогоном: `bash src/control/profiles/check.sh
<RUN>.env` — печатает ключи, чьи значения в профилях и в env прогона различаются
(по умолчанию активный стек dphold + dpvins + vins + loiter; `vinshold/` — только явно).

## Что сравнивать

Полёты по ярусам под порывами меряет `src/lab/gust_hold_compare.py` (пик за
порыв = жёсткость, остаток за цикл = якорь); гейт здоровья — `vins_sane_replay.py`.
Итог эталона 2026-09-05: DpHold пик 2.4–2.8 м, DpVins 6.3–9.5, остаток за цикл
DpHold 0.8–1.5 (копится по ветру), DpVins 0.1–0.4 (возвращается) — память
`dphold-vs-dpvins-gusts`.
