## Корень: частичный сегмент ВЫБРАСЫВАЕТСЯ

`flow_estimator.py`, блок пересева опоры (≈444–464):

```python
seg_full = (self._kf_logs_prev is not None
            and abs(self._kf_logs_prev) >= self.kf_seg_max)
if (self._kf_pending or self.kf_cur is None
        or len(self.kf_cur) < self.kf_min_pts
        or alt_drift > self.kf_alt_max          # <-- вот этот повод
        or self._kf_reject_run > self.kf_reject_max
        or seg_full):
    if not self._kf_pending and self.kf_cur is not None:
        trust = seg_full or (len(self.kf_cur) < self.kf_min_pts)
        if trust and self._kf_logs_prev is not None:
            self.kf_acc += self._kf_logs_prev   # смещение переживает пересев
            self.kf_segs += 1
        else:
            self.kf_reseeds += 1                # смещение ПОТЕРЯНО
```

Ушла высота больше порога — опора пересевается, а накопленное с прошлого пересева
смещение объявляется недостоверным и **выбрасывается**. Дом переезжает туда, где борт
оказался. За 20 с висения таких выбросов **31–39 штук** — примерно дважды в секунду.

Корреляция доли сохранённых сегментов с крутизной канала — **+0.58** (n=10), **+0.69**
без слепого прогона. Меряно ВНУТРИ `D2s`, паспорт для этого не нужен.

Порог сам по себе обоснован не под наш режим: в комментарии он посчитан как «6 % высоты,
**на 5 м это 30 см**», а летаем мы на 3 м — те же 6 % дают 19 см при размахе колебаний
ALT_HOLD 0.2–0.4 м. Порог срабатывает на штатной болтанке удержания высоты.

**Вывод: борт вперёд ничего не толкает.** Контур забывает точку удержания дважды в
секунду, поэтому он умеет только демпфировать и не умеет возвращать.

## Решение (принято): гейт остаётся, пересев по высоте уходит

Ключевое наблюдение: гейт по высоте **уже есть**, отдельно от пересева —
`flow_estimator.py:398`:

```python
if alt_drift > self.kf_alt_max:
    kf_ok = False            # высота ушла — кадру не верим, регулятор не командует
```

То есть на уходе высоты контур и так молчит. Пересев на том же условии — **чистая
дополнительная потеря**, ничего не защищающая.

Дальше — три факта, которые делают пересев по высоте ненужным:

1. **Вклад высоты в масштаб мгновенный.** `alt_drift = |log(alt / kf_alt0)|` считается по
   ТЕКУЩЕЙ высоте. Вернулась высота — сигнал восстановился сам, опору чинить не надо.
2. **Опора переживает заморозку с запасом.** Фича живёт медиану 284 кадра ≈ 9.4 с при
   30 Гц (замер `keyframe_track.py` по G1), а выброс высоты на болтанке — доли секунды.
   Порядок величины в нашу пользу.
3. **Настоящий набор высоты пересева требует** (замер H6_kd: 1.5 → 4.8 м, дребезг
   `kf_logs` 0.02–0.04, kd даёт 1000 PWM, слю размазывает в −70 PWM, рама на 6.9°,
   самодельные 1.5 м/с). Но там высота НЕ возвращается — значит различать надо по
   **длительности**, а не по величине.

### Правка: блок опоры ЗАМИРАЕТ на время ухода высоты

Пока `alt_drift` выше порога, блок опоры не делает **ничего**: не закрывает сегмент, не
пересевает, не обновляет `_kf_logs_prev` — держит последнее хорошее значение. Гейт при
этом работает как сейчас, контур молчит.

```python
frozen = alt_drift > self.kf_alt_max
if frozen:
    self._alt_out += dt          # сколько подряд высота вне порога
else:
    self._alt_out = 0.0

# закрытие сегмента и пересев — ТОЛЬКО на достоверных кадрах
if not frozen:
    seg_full = ...               # как сейчас
    if seg_full or мало_точек or серия_отбраковок or pending:
        ...                      # как сейчас
elif self._alt_out > self.kf_alt_hold:
    # высота НЕ вернулась — это настоящий набор, опора протухла честно
    self.kf_acc += self._kf_logs_prev   # последнее ХОРОШЕЕ значение, ему верим
    self.kf_segs += 1
    self._seed(gray)
```

Что это даёт сверх «просто поднять порог» (что и делает свип `E1`):

1. **Гейт остаётся жёстким** — `kf_alt_max` возвращается на 0.06. На болтанке контур не
   командует по кадру, где масштаб испорчен высотой. Поднятый порог ослабляет ГЕЙТ ТОЖЕ,
   то есть покупает память ценой вранья в сигнале.
2. **Смещение переживает болтанку.** Вклад высоты мгновенный, вернулась высота — сигнал
   продолжился с того же места, чинить нечего.
3. **Артефакт высоты не уедет в накопитель.** Сейчас `seg_full` может сработать на
   испорченном `kf_logs` (0.027 набирается высотой легко) и записать подъём в копилку как
   перемещение, причём с пометкой «доверенный». Заморозка это закрывает.
4. **Даже настоящий набор больше не стирает дом** — банкуем последнее хорошее значение
   вместо `kf_reseeds += 1`.

Новая ручка одна: **`kf_alt_hold` ≈ 1.5 с** — между болтанкой ALT_HOLD (~0.3 с) и набором
(десятки секунд). Различаем по длительности, а не по скорости набора: не нужен
дифференциатор высоты со своим шумом, хватает одного счётчика. Вывести в `config.py` и env.

Ожидаемый эффект: дом перестаёт переезжать на каждой болтанке, накопитель `kf_acc` копит
смещение, крутизна канала перестаёт плавать в 10 раз — и контур получает возможность не
только гасить, но и возвращать.

## Что проверяет свип `E1` (в полёте)

`kf_alt_max` = 0.06 / 0.15 / 0.25 / 0.40, по одному прогону, остальное — как `D2s`.
Свип НЕ является лечением (лечение — в логике выше), он проверяет, что механизм
опознан верно.

Первичная метрика — **доля сохранённых сегментов** `kf_segs/(kf_segs+kf_reseeds)`:
прямой счёт того, что ручка делает механически, почти детерминирована. Подняли порог,
а доля не выросла — дорога неверная, и это видно сразу по четырём прогонам.

Вторичные: крутизна канала (`gain.py`), продольный уход (`axis_split.py`).
Дополнительное предсказание: длиннее сегменты → реже обнуления → должны поехать размах
и период качелей (в `D1s` продольный размах 15.7–24.7 м с периодом 12–15 с).

### Команда прогона

Скрипт пишется ЦЕЛИКОМ heredoc'ом — `sed`-правкой по числовому шаблону нельзя, `N=1`
цепляет `OSIGN` и `CMD_GAIN`. Отвязанно (`setsid nohup`), чтобы пережить обрыв связи.

```bash
cat > /tmp/e1_run.sh <<'SH'
#!/usr/bin/env bash
set -u
cd /root/13.17/docker/sim
for pair in "E1a:0.06" "E1b:0.15" "E1c:0.25" "E1d:0.40"; do
    name="${pair%%:*}"; val="${pair##*:}"
    echo "======== СВИП E1: $name  kf_alt_max=$val ========"
    env N=1 PREFIX="$name" GDRIVE_UP=1 MP4=1 \
        BS_STAB=DpHold BS_MISSION="climb3,hover20,land" \
        BS_KF_ALT_MAX="$val" \
        BS_FENCE=25 BS_FLOW_OBS=1 BS_SLEW=300 BS_THROTTLE_CLIMB=1800 \
        BS_ARM_BUDGET=80 BS_CLIMB_BUDGET=120 BS_MODE_BUDGET=80 BS_LAND_BUDGET=180 \
        BS_ROLL_KP=48 BS_ROLL_KI=0 BS_ROLL_IMAX=150 BS_ROLL_SMOOTH=25 \
        BS_ROLL_OSIGN=1 BS_ROLL_CMD_GAIN=10 \
        BS_PITCH_KP=1500 BS_PITCH_KI=0 BS_PITCH_KD=1500 BS_PITCH_SMOOTH=9 \
        BS_PITCH_OSIGN=1 BS_PITCH_CMD_GAIN=0 \
        BS_YAW_KP=20 BS_YAW_KI=0 BS_YAW_SMOOTH=5 \
        bash /root/13.17/src/lab/hover_series.sh
done
echo "######## СВИП E1 ЗАВЕРШЁН ########"
SH
cd /root/13.17/docker/sim && setsid nohup bash /tmp/e1_run.sh \
  > /root/13.17/docker/sim/output/E1.log 2>&1 < /dev/null & disown
```

Разбор (нода не нужна, контейнер одноразовый — стенд между сериями лежит):

```bash
docker run --rm -v /root/13.17/src/lab:/lab:ro \
  -v /root/13.17/docker/sim/output:/out:ro ros:humble-ros-base bash -lc \
  'source /opt/ros/humble/setup.bash
   for b in E1a1 E1b1 E1c1 E1d1; do python3 /lab/kf_health.py /out/${b}_bag; done'
```

`kf_health.py` даёт сегменты/пересевы/выбросы, `axis_split.py` — уход по осям.
⚠️ Обе принимают ПОЛНЫЙ путь к бэгу (`/out/<имя>_bag`), от голого имени печатают
только шапку.

**Механизм подтверждён.** Доля растёт монотонно и насыщается — ручка делает ровно то, что
насчитано по коду, выбросы сегментов действительно правят балом.

**Лечением свип не является.** Полёт от поднятого порога не выправляется: 21 / 13.5 /
качель / забор лежит внутри разброса стенда (`D2s`: 5 заборов из 10 на одном конфиге).
Так и должно быть — порог служит ещё и затвором, и задранный порог пускает в контур
кадры, где масштаб испорчен высотой. Память куплена ценой вранья в сигнале.

Отдельно стоит форма ухода. При 0.06 и 0.15 борт просто **уезжает** — контур гасит, но
дома не помнит. При 0.25 он впервые **разворачивается**: ушёл на 17 м назад, отработал и
проехал через ноль на +13 вперёд, полный размах 30 м за один период 28 с. Память вернулась
— контур получил власть и сразу показал, что с нынешними гейнами он не держит, а
раскачивает. Настраивать контур, который забывает точку дважды в секунду, было невозможно
в принципе: не за что зацепиться.

**Не объяснено:** выбросы 0 / 0 / 33 / 1 — немонотонны, связи с порогом нет. Первое
прочтение («задранный затвор пускает грязь, её ловит ограничитель шага») опровергается
последней строкой. Оставлено как открытый факт.

### Что ограничивает: крутизна канала гуляет в 14 раз

Замер по каждому прогону (`pitch_wire.py`, продольный путь считается интегралом проекции
скорости на нос борта — сигнал живёт в связанной системе, а не в мировой):

| | s1 | s2 | s3 | s4 | s5 | s6 | s7 | s8 | s9 | s10 |
|---|---|---|---|---|---|---|---|---|---|---|
| log/м | 0.0039 | 0.0189 | 0.0037 | 0.0040 | 0.0033 | 0.0014 | 0.0097 | 0.0102 | 0.0015 | 0.0018 |
| corr | +0.40 | +0.83 | +0.55 | +0.83 | +0.42 | +0.21 | +0.62 | +0.65 | +0.50 | +0.25 |

Медиана **0.0038**, среднее 0.0058 ± 0.0056, разброс **0.0014…0.0189 — четырнадцатикратный**.
А `pitch_kp=1500` считался под 0.0061 (см. `config.py`): на медиане контур в 1.6 раза мягче
расчётного, а по прогонам его эффективный гейн гуляет от 0.23× до 3.1× от задуманного.

**Настраивать `kp` в таких условиях нельзя.** Свип по гейну мерил бы не гейн, а то, какая
крутизна выпала прогону. Это же обесценивает значения кампании `N`: они снимались против
того же плавающего канала.

- corr(крутизна, размах курса) = **+0.81**
- corr(крутизна, |уход|) = +0.43

Курс связан с уходом теснее, чем сама крутизна. Причинность из этого не следует: и большой
уход, и большое рыскание, и «хорошая» крутизна одинаково растут из длинных бурных прогонов
(больше смещение — больше сигнала, лучше ложится регрессия). Но факт остаётся фактом: ось
рыскания на трёх осях НЕ держит, а опорный канал меряет масштаб созвездия, которое поворот
камеры уводит из кадра.

## Отказ курса: сигнал ломается ДВИЖЕНИЕМ, а не связкой осей

Проверка прямая и мимо контура (`yaw_wire.py` + интегральный тест): сравниваем истинный
разворот за висение с накопленным визуальным `∫flow_yaw·dt / S`, где `S = 0.324` px/кадр
на °/с (паспорт Y4). Доля = сколько разворота сигнал вообще увидел.

| стенд | доля увиденного разворота |
|---|---|
| ось курса ОДНА, соседи на оракулах (`Y5s1-3`, `Y2_kp0`) | **+0.96 ± 0.12** (n=4) |
| три оси на `Dp` (`E2`) | **−0.09 ± 0.02** (n=6) |

Слева датчик меряет курс **один в один** — паспорт `S` подтверждается независимо. Справа
он показывает девять процентов разворота, да ещё **с обратным знаком**, и разброс при этом
крошечный (±0.02) — то есть это не шум, а систематика.

Контур ведёт себя соответственно: пока борт разворачивается на 71…177°, ошибка не выходит
за ±3 единицы (≈10° в пересчёте), σ PWM 8…25, потолка выход не касается НИ РАЗУ. **Ось не
борется и проигрывает — она не борется.**

Механизм записан в самом коде, в комментарии над расчётом (`flow_estimator.py`): yaw-гиро
намеренно НЕ вычитается, и остаток считается чистым визуальным курсом при условии — «в
ДАЛЬНЕЙ сцене трансляция ≈0». В `Y5s` соседние оси держали оракулы, борт стоял, условие
выполнялось. В `E2` борт идёт 1…4 м/с, и трансляция заливает канал курса. Контур честно
нулит то, что видит, а видит он в основном снос.

Контроль на третьем стенде: `nostab_run5` (без стабилизации вовсе, борт уезжает) даёт
долю −10 — канал забит трансляцией ещё сильнее. Три точки выстраиваются по скорости борта,
а не по числу включённых осей.

Это ровно тот случай, что записан в `tune.md` как обобщение: **ось, измеренная с оракулами
на соседях, проверена только на неподвижном планере.** Теперь у него есть цена в числах.

Следствие для corr(размах курса, |уход|) = +0.69: причинность не «рыскание рождает уход»,
а общий корень — трансляция портит канал курса и она же есть уход.

# РАЗВОРОТ: положение → СКОРОСТЬ (серии E3–E8)

Всё, что выше, — попытки починить продольный канал ПОЛОЖЕНИЯ. Он был вылечен по всем
найденным дефектам и всё равно не дал удержания. Развязка оказалась не в починке, а в
смене вопроса: пре-VINS слою не нужно возвращать борт в точку, ему нужно его ОСТАНОВИТЬ.

## Что чинилось и чем это кончилось

| серия | что правилось | уход | внутри 10 м | v_макс |
|---|---|---|---|---|
| `D2s` | — (база) | 20.9 м | — | — |
| `E2` | опора замирает на уходе высоты | 23.2 м | 52 % | 3.82 |
| `E3` | канал курса: вычтен снос | 20.8 м | 70 % | 5.85 |
| `E5` | сегмент по СРОКУ (2 с) | 29.6 м | 70 % | 6.73 |
| `E6` | сегмент по ДОЛЕ картинки (0.30) | 20.7 м | 66 % | 4.43 |
| `E7` | сегмент засчитывается всегда | 24.3 м | 66 % | 4.91 |
| **`E8`** | **тангаж по СКОРОСТИ (вид сверху)** | **3.5 м** | **100 %** | **1.63** |

Пять серий подряд не сдвинули уход с двадцати метров. Каждая правка была настоящей —
каждая подтверждена офлайн-замером на записанных кадрах, — и ни одна не помогла.

## Почему положение не работало, а скорость работает

**Улика лежала в данных с самого начала.** Крен у нас всегда был осью ПО СКОРОСТИ,
тангаж — ПО ПОЛОЖЕНИЮ, и уход по осям на одной раме и одних кадрах расходился втрое-всемеро:

| серия | вперёд (положение) | вбок (скорость) |
|---|---|---|
| E2 | +20.2 ± 13.7 м | +5.8 ± 7.5 м |
| E3 | −3.0 ± 27.3 | −0.9 ± 3.2 |
| E6 | +17.0 ± 23.8 | −2.5 ± 5.9 |
| E7 | +3.6 ± 29.7 | −1.0 ± 3.7 |

Читалось это как «продольный канал слабее», а было — «положение как закон хуже скорости».

Причина в накоплении. Положение у нас — СУММА закрытых сегментов, и любая ошибка в
сумме вечна. Отсюда весь список отказов, который мы разбирали неделю: выброшенный
сегмент (`E2`), квантование в ±0.03 независимо от хода (`E6`), стёртая память на серии
отбраковок (`E7`), знак трети сегментов наоборот. У СКОРОСТИ накопления нет — эти
отказы физически не могут существовать.

Скорость отвергли когда-то потому, что `flow_longitudinal` (медиана покадрового
вертикального сдвига) дала corr −0.22 с истинной скоростью. Но мерилась она там, где
93 % точек сидят на линии горизонта и почти не движутся (замер `feat_lo`). То есть
отвергали не закон, а плохую его реализацию.

## Что дало метрику: ВЫПРЯМЛЕНИЕ (IPM)

Корень плавающей цены метра — неконтролируемая ГЛУБИНА точек: точка на земле в 5 м даёт
при ходе 0.25 м целых 0.05 log, точка у горизонта в 50 м — 0.005. Смесь меняется от
кадра к кадру, вместе с ней крутизна (разброс 14×) и иногда знак.

Полоса земли перед бортом выпрямляется в вид сверху по высоте и углам — и продольный ход
становится равномерным сдвигом с ИЗВЕСТНОЙ ценой пикселя. Геометрия у нас рабочая:
камера наклонена на 15°, обзор 58.7°, нижний край смотрит под 44°, строка 360 — под 26°;
при высоте 3 м это земля с 3.1 до 6.3 м, ровно там, где детектор и так ищет точки.

Замер (`ipm_flow_test.py`, три бэга с кадрами) — путь против истины:

| | продольная | боковая |
|---|---|---|
| E5f1 | +1.00 corr +0.99 | +0.91 corr +0.64 |
| E6f1 | +1.03 corr +1.00 | +1.06 corr +0.96 |
| E7f1 | +0.97 corr +1.00 | +1.09 corr +0.81 |

**Метры меряются метрами, без калибровки — из одной высоты.** Скорость (наклон МНК в
окне 0.5 с): крутизна 0.91–0.94 при corr 0.76–0.84 и ошибке 0.65–0.82 м/с.

Две ловушки, которые стоили времени и обе были в МОЁМ разборе, а не в идее:
- занижение в 3–5 раз объяснялось «сцена не плоская» и «знак тангажа» — оба опровергнуты
  замером. Настоящая причина: `rel_alt` в бэге штампован WALL-временем, кадры — SIM, при
  RTF≈0.07 шкалы расходятся в 14 раз, и интерполяция подставляла высоту от начала прогона.
  В ПОЛЁТЕ этого нет, нода читает живой топик;
- знак поворота в проекции был перевёрнут — земля в 3 м падала в строку 1098 вместо 548.
  Поймано численной проверкой геометрии ДО первого прогона.

## Раскачка и свип `pitch_rate_kp` (F1)

Замеченное по видео: борт не улетает, но качается по обеим осям. Замер подтвердил —
тангаж качал втрое сильнее крена (|v| 0.66 против 0.23 м/с, период 2–3.3 с). Это подпись
предельного цикла: запаздывание петли ~1 с (окно МНК 0.25 + ограничитель 0.5 + рама 0.27),
а П-регулятор с таким запаздыванием качает с периодом вчетверо большим.

Свип (по прогону на точку, `DpHoldR`):

| kp | размах | v СКО | период | уход |
|---|---|---|---|---|
| 200 | 1.90 м | 0.54 | 4.5 с | 1.7 м |
| 100 | 9.20 м | 0.18 | нет | 9.5 м |
| 50 | 9.21 м | 0.31 | нет | 7.9 м |

**Гейном выбирается, какую из двух болезней терпеть.** Высокий — держит близко, но
качается; низкий — не качается, но уползает. Вылечить обе разом может только позиция:
у чистого демпфера скорости нет точки равновесия в пространстве.

⚠️ Обмен НЕ монотонный (на 50 дрожь снова выросла), и разброс стенда того же порядка:
та же настройка kp=200 дала |v| 0.66 в `E8` и 0.47 в `F1a1`. По одному прогону на точку
выбирать нельзя. За kp=200 стоит семь прогонов (уход 1.7–4.8 м), за kp=100 — один.

## Серии по гейну: тангаж (`F2`/`F3`) и крен (`G2`/`G3`)

Свип по прогону на точку выбирать не дал (разброс стенда того же порядка, что разница
между точками), поэтому обе оси перегнаны СЕРИЯМИ n=5 — `rate_gain_series.sh`.

**Тангаж** (`DpHoldR`, сигнал `ipm_vfwd`): kp=100 против kp=50 — разницы, которую видно
на пяти прогонах, нет (t=1.27). Дефолт 100 обоснован не победой, а тем, что он «не хуже
и держит внутри круга 5/5 против 2/5». kp=200 не рассматривался: лучший уход (1.7–4.8 м),
но период 4.5 с и СКО скорости 0.54 — раскачку не корректирует ничто, а стик корректирует
позицию. `pitch_rate_kp: 200 → 100`.

**Крен** (`DpHoldM`, обе оси в метрах, сигнал `ipm_vlat`):

| kp | уход м | СКО v_lat | вбок | внутри 10 м |
|---|---|---|---|---|
| 120 | 8.0 ± 7.5 | 0.79…1.20 | — | 4/5 |
| 60 | 3.8 ± 2.2 | 0.53…0.66 | −0.28 ± 1.75 | 5/5 |
| 30 | **2.6 ± 1.2** | **0.10…0.45** | −0.79 ± 1.70 | 5/5 |

Лучший прогон кампании — `G3s2`: уход 0.82 м, конечная скорость 0.07 м/с.

Здесь обмен «спокойствие против сноса» НЕ работает: 30 лучше 120 и по дрожи, и по сносу
разом. Значит 120 стоял ВЫШЕ предельного цикла и сам себя разгонял. 120 — это пересчёт
пиксельного `roll_kp=48` (48 × 2.42 px/(м/с) ≈ 116), и пересчёт оказался ловушкой: он
переносит ЧУВСТВИТЕЛЬНОСТЬ, но не запас устойчивости — у `ipm_vlat` своё запаздывание
(окно МНК 0.5 с), и на нём тот же гейн уже качает. **Правило: пересчитанный гейн — это
стартовая точка свипа, а не подобранное значение.**

Заодно ушёл систематический боковой снос: на пиксельном канале он был −3.02 ± 0.80 м и
ВСЕГДА в одну сторону, на метрическом при kp=30 — −0.79 ± 1.70 м, знак случайный.
Односторонний снос был не ветром, а ценой канала.

`roll_rate_kp: 120 → 30`.

**Проверка kp=15 (`H2s`) — минимум пройден, тренд оборвался.** Серия остановлена после
двух прогонов, оба однозначны:

| прогон | уход м | вбок | СКО v_lat | \|v_lat\| |
|---|---|---|---|---|
| H2s1 | 9.1 | −7.6 | 0.16 | 0.38 |
| H2s2 | 29.6 | −25.9 | 0.38 | 1.26 |

Спокойствие ещё выросло (пик 0.82 м/с — лучший в кампании), а борт при этом уехал за
забор. Подпись видна не в СКО, а в отношении **|v| к СКО**: 0.38 при 0.16 и 1.26 при
0.38 — скорость почти ПОСТОЯННАЯ, то есть демпфер не додавливает смещение, а сопровождает
его. H2s2 к концу ещё и разгонялся (0.71 → 1.58 м/с).

⚠️ **Отсюда мерка:** одной СКО скорости для выбора гейна МАЛО — она падает и когда ось
успокоилась, и когда ось сдалась. Различает их `|v|/СКО`: у живого демпфера скорость
знакопеременная (|v| ≈ СКО), у сдавшегося — односторонняя (|v| ≫ СКО). На kp=30 это
0.12/0.14 … 0.43/0.45 ≈ 1, на kp=15 — 2.4 и 3.3.

## Где мы сейчас и что дальше

Решение по развилке: **сначала вменяемые три оси на демпферах, снос терпим, позицию не
трогаем.** Критерий выбора гейна тогда не «минимум ухода» (его без позиции не будет), а
СПОКОЙСТВИЕ при сносе, который не выносит борт за разумные пределы до инициализации VINS.

1. ✅ **Статистика по гейну тангажа** — серии `F2`/`F3`, дефолт `pitch_rate_kp=100`.
2. ✅ **Крен приведён той же меркой** — серии `G2`/`G3` на `DpHoldM`, дефолт
   `roll_rate_kp=30`. Обе оси теперь метрические и подобраны сериями.
3. ✅ **Минимум по крену найден** — серия `H2s` (kp=15) остановлена на двух прогонах,
   оба уехали (9.1 и 29.6 м). Дефолт остаётся 30.
4. **Вычистить угловую утечку из выпрямления** (см. ниже) — самая крупная ИЗМЕРЕННАЯ
   поправка канала, и зрение для неё не нужно: обе угловые скорости даёт гироскоп.
5. **Укоротить окно скорости** 0.5 → 0.3 с: режет запаздывание вдвое, сигнал теряет мало
   (corr 0.75–0.82 против 0.76–0.84). Отдельным шагом, не вместе с гейном.
6. **Открыть стик на тангаж** (`pitch_rate_cmd_gain`): по выбранному критерию позицию
   правит оператор, а сейчас ось к стику глухая (у крена `roll_cmd_gain=10` есть).
7. Позиционный член — ПОТОМ и поверх скоростного, уже на метрическом канале, где путь
   считается интегралом честных метров, а не суммой сегментов с плавающей ценой.
