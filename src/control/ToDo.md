## Что установлено измерением

Всё ниже — числа из bag'ов, не рассуждения. Источник указан.

### 1. Знак канала pitch перевёрнут

```
roll :  +0.060 °/PWM   corr +0.97      ← ведёт себя как задумано
pitch:  −0.037 °/PWM   corr −0.58      ← противоположно
статика при ANGLE_MAX=45°:  +0.090 °/PWM
```

Обе оси идут через один `_cmd_to_pwm` (`control_stack.py`: `1500 + c·400`), значит
одинаково правильными быть не могут. Roll соответствует намерению (`c_right=+1` → вправо),
следовательно перевёрнут pitch: `c_fwd=+1` («вперёд») физически даёт нос вверх и полёт
НАЗАД. Сходится с конвенцией ArduPilot: RC2 вверх = стик на себя = нос вверх.

Последствие: коррекция демпфера по продольной оси толкает дрон туда, куда он уже едет —
положительная обратная связь. Этим одним пунктом объясняется разгон в прогоне `DpHold`.
Источник: `gzprobe_run4_bag`, `nostab_run5_bag` (замер на обоих, знак совпал).

### 2. Борт со стиками в центре не держит горизонт

```
t=  0.0  тангаж +0.00°   vx −0.06
t= 51.5  тангаж +1.11°   vx +0.20
t=130.7  тангаж +1.62°   vx +1.12      (стики ровно в центре всю фазу)
```

Постоянные **+1.2° на нос** → a = g·tg(1.2°) = 0.21 м/с² → к концу набора 1.1 м/с, к концу
миссии 8 м/с. Курс при центральном yaw-стике уезжает равномерно на **+2.8°/с**.
Кандидаты: калибровка горизонта в eeprom SITL (`AHRS_TRIM_*`), трим RC-каналов
(`RC1..4_TRIM ≠ 1500`). Не проверено.
Источник: `nostab_run5_bag`, фаза набора.

### 3. Поток команд демпфера не успевает материализоваться

```
пересчёт команды:             33 мс   (по кадру, 30.3 Гц sim)
выход борта на заданный угол: 200–400 мс
реализация: гладкая команда 67% крутизны, рваная 41%
```

Плюс знакопеременность: `flow_lon` = −4.8, −16.4, **+19.2**, −18.1 px/кадр → команда +57,
+131, −150, +144 PWM. Среднее знакопеременного потока ≈ 0. Борт отрабатывает огибающую,
а не значения.

Важно: «импульс» и «удержание стика» в нынешнем механизме — одно и то же. `OverrideRCIn`
это положение стика = целевой угол, живёт до следующего сообщения. Ширина импульса
задаётся только тем, как долго мы шлём одно значение.

### 4. Амплитуда коррекции порядка помехи

Типичная |команда| — десятки PWM (1–3°) при собственном смещении борта 1.2°.
Средние по фазам: `DpHold` −24.5, зонд −24.9, без стабилизации −34.9 PWM.

### 5. Перцепт: сигнал слабый, но не нулевой

| прогон | условия | flow_lat ↔ v_вбок | flow_lon ↔ v_вперёд |
|---|---|---|---|
| `dphold_run3` | разгон до 30 м/с, LK развалился | −0.08 | −0.01 |
| `nostab_run5` | 1–8 м/с, курс уплыл на 29° | **−0.52** / −1.2 px·кадр⁻¹·(м/с)⁻¹ | +0.20 / +0.7 |
| геометрия down-look дала бы | | +4.3 | +4.3 |

Боковой сигнал есть — слабый и обратного знака к down-look-конвенции; продольный почти
пуст. **Но ни один замер не сделан в чистых условиях**: во всех прогонах дрон разгонялся
сам, вращался и управлялся перевёрнутым каналом. Судить перцепт по этим данным нельзя.

Геометрическая причина слабости известна: камера смотрит ВПЕРЁД с наклоном 15°
(`worlds/iris_cam/model.sdf:907` — `0.15 0 0.05 0 0.26 0`), земля в центре кадра на ~13 м,
верх кадра — горизонт. Трансляционный поток ∝ v/Z и тонет в остатке derotation.

### 6. `GzYawHold` раскручивает, а не держит

С ним курс ушёл на **−150° за 10 sim-сек**; без него естественный дрейф +29° за весь полёт.
Вероятная причина: gz-одометрия даёт курс в ENU (CCW+), рыскание борта в NED (CW+) →
П-регулятор с перевёрнутым знаком и рулём-по-скорости раскручивается.
Источник: `gzprobe_run4_bag` vs `nostab_run5_bag`.

### 7. Частоты контура — в норме, не причина

```
тик контура   20.00 Гц sim   (dt 36–64 мс)
камера        30.30 Гц sim   (dt 8–76 мс, джиттер штампа)
одометрия     50.00 Гц sim
RTF 0.055 → по стенным часам 1.1 / 1.7 / 2.7 Гц
```

Гипотеза «джиттер штампа кадра течёт в derotation» проверена и **не подтвердилась**
(corr(джиттер, |flow|) ≈ 0.02).

## Очередь работ

Порядок важен: пока объект едет сам и канал перевёрнут, любой замер законов управления
меряет дрейф, а не законы.

### 1. Починить знак pitch — БЛОКЕР

`ControlStack.update`: `pitch=_cmd_to_pwm(intent.c_fwd)` → инвертировать. Обновить тесты,
которые фиксируют текущее поведение (`test_profile_motion`, `test_multiaxis_stack`).
Проверить заодно, не задваивается ли инверсия с `pilot_pitch_sign` (`RcTransmitter`) и с
`pitch_osign` демпфера — после правки прежние подобранные знаки станут неверными.

**Критерий:** `mv_bkwd` даёт PWM < 1500 и физически летит назад.

### 2. Прогон-подтверждение канала

```bash
BS_STAB="none" BS_MISSION="climb3,mv_bkwd6,land" BS_MV_LEVEL=0.375 BS_FLOW_OBS=1
```

**Критерий:** наклон −9…−13°, разгон назад ~2 м/с², к концу сегмента ≈12 м/с и ~40 м
позади старта. Не сошлось — разбирать доставку команд, дальше по списку не идти.

### 3. Устранить смещение борта (+1.2°, +2.8°/с по курсу)

Прочитать `AHRS_TRIM_X/Y` и `RC1..4_TRIM` у SITL (чтение параметров, прогона не требует).
Если дело в калибровке — пересобрать eeprom (`make sitl-cal`); если в триме — привести к
1500 либо учесть офсет в `RC_CENTER` поканально.

**Критерий:** со стиками в центре |тангаж| < 0.2° и дрейф курса < 0.3°/с за 20 sim-сек.

### 4. Знак yaw и `GzYawHold`

Разобраться с ENU/NED в `GzHold` (`yaw_sign`, сравнение `_yawsp` с `s.gt_yaw`).

**Критерий:** курс удерживается в ±5° за 20 sim-сек висения.

### 5. Перемерить перцепт на чистом движении

Симметричный прогон без стабилизаторов: набор → назад → вперёд → вбок → посадка, умеренные
скорости, курс не уезжает (после п.3–4). Считать корреляцию и крутизну по каждой оси.

**Критерий:** получен честный ответ, годится ли `flow_lateral`/`flow_longitudinal` как
сигнал скорости, и с каким масштабом (px/кадр на м/с).

### 6. Форма команды демпфера

Сейчас выход PID идёт в RC как есть: без сглаживания, без ограничения скорости изменения,
шириной в один кадр. Нужно привести к тому, что борт способен отработать: удержание
≥4–8 тиков (0.2–0.4 sim-сек), slew-limit, амплитуда выше смещения объекта. Кандидаты —
ZOH на N тиков, фильтр выхода, включение `roll_smooth`/`pitch_smooth` (сейчас = 1, выкл).

**Критерий:** реализация команды в угол ≥ 60% статической крутизны (сейчас 41%).

### 7. `PulseTrain` — генератор импульсов для system-ID

`Excitation` в arch2 — заглушка (`NoExcitation`), `BS_RE_*` в `capture_scene.sh` это легаси
монолита и никуда не заведены. Нужен `PulseTrain(axis, amp, on_ticks, period_ticks, nrep,
policy)` + сборка из cfg + проброс env, чтобы снять отклик Δv(ширина) и Δv(амплитуда).
Делать ПОСЛЕ п.3 — иначе меряем дрейф.

### 8. Геометрия камеры (если п.5 покажет, что сигнала нет)

Варианты по убыванию прямоты: отдельный down-look сенсор в SDF (тогда px/кадр ∝ v/h —
ровно та математика, на которую написан `_FlowDamper1D`); `divergence` вместо
`longitudinal` для продольной оси (looming физически корректен для вперёд-смотрящей
камеры, уже считается в `FlowEstimator`, но `DpPitchHold` его не использует); признать
трансляционный hold недостижимым с пилотной камерой и держать только yaw до VINS.

⚠️ На борту камера тоже пилотная, вперёд — это ограничение не симуляционное.

### 9. Диагностика и инструменты

- `/flow_dbg3` с командой yaw и углами борта: сейчас yaw-команды в bag нет вообще.
- Закрепить измерительные скрипты в репе (`src/lab/`): разбор по фазам, замер знака канала
  `команда → угол`, сверка перцепта с истинной скоростью. Сейчас живут во временном
  каталоге сессии и теряются.

## Не закоммичено (в рабочем дереве)

- `DpPitchBack` — зонд: расчёт `DpPitchHold`, выход выпрямлен назад (`u = −|u|`).
  Метка `is_probe`; `_hold_stack()` зонды отфильтровывает (не ставит на набор/посадку).
- `flow_observe` (`--flow-observe` / `BS_FLOW_OBS=1`) — поднять зрение и писать
  `/flow_dbg*` без демпфера в стеке.
