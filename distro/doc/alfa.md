# Alfa AWUS036ACH на борту (Realtek RTL8812AU)

Внешний Wi-Fi для ssh/телеметрии с дрона — дальше и мощнее штатного M.2-модуля Jetson
(`wlP1p1s0`, RTL8822CE, антенна на раме). Всё ниже — разбор 2026-09-21, ветка
`laptop_drone`. Правило то же, что для всего борта: конфиги и скрипты — в `distro/`,
на борт — через `deploy.sh`, руками на Jetson ничего не менять.

**Железо.** Чип RTL8812AU, USB ID `0bda:8812`, 2T2R, 2.4 + 5 ГГц. Разъём на адаптере —
**USB 3.0 micro-B** (широкий, двухсекционный). Ток: в USB 3.0-режиме запрашивает
**800 мА**, в USB 2.0 — 500 мА; на передаче тянет до ~0.9 А.

## 1. Подключение: что мы прошли

**Симптом.** Адаптер воткнут коротким угловым кабелем, в `dmesg` бесконечный цикл
(31 попытка с загрузки), на любом порту:
```
usb 1-2.1: new high-speed USB device number 4 using tegra-xusb
usb 1-2.1: Device not responding to setup address.
usb 1-2.1: device not accepting address 7, error -71
usb 1-2-port1: Cannot enable. Maybe the USB cable is bad?
usb 1-2-port1: attempt power cycle
```
`mavlink-router` при этом падает («Start request repeated too quickly»), MAVROS молчит —
если полётник тоже на USB (`/dev/ttyACM0`), симптомы легко перепутать.

**Что это НЕ было.** Не «зарядный кабель»: строка `new high-speed USB device` означает,
что хост договорился о 480 Мбит по D+/D− — линии данных есть. У чисто зарядного
кабеля в `dmesg` тишина. Не драйвер: устройство не доходит до стадии, где он нужен.
Не порт: два разных разъёма — та же ошибка.

**Что это было: micro-USB 2.0 кабель в USB 3.0 micro-B гнезде.** Узкий штекер
физически входит в левую половину широкого гнезда, щёлкает, держится — но
SuperSpeed-пар в нём нет, а тока он даёт 0.5 А. Ноутбук такое вытягивает (адаптер
«работает» на USB 2.0), порт Jetson — нет: `error -71`.

```
Гнездо адаптера (USB 3.0 micro-B):        ПРАВИЛЬНЫЙ штекер (~12 мм):   НЕПРАВИЛЬНЫЙ (~7 мм):
   ┌──────────┬────────────┐               ┌──────────┬────────────┐     ┌──────────┬────────────┐
   │ ▄▄▄▄▄▄▄▄ │ ▄▄▄▄▄▄▄▄▄▄ │               │██████████│████████████│     │██████████│            │
   └──────────┴────────────┘               └──────────┴────────────┘     └──────────┴────────────┘
     основная    SuperSpeed                  закрывает всё гнездо          только левая половина
```

**Как отличить кабель, не гадая:**
1. Штекер в адаптер закрывает **всё** гнездо (см. выше).
2. В Type-A конце **9 контактов** (4 на язычке + 5 глубже у задней стенки) — USB 3.0;
   4 контакта — USB 2.0. Синий язычок и «SS» на дешёвых кабелях рисуют не по делу.
3. Контрольный — воткнуть и посмотреть шину. Адаптер на **`Bus 2` / 5000 Мбит** =
   кабель USB 3.0; на `Bus 1` / 480 — USB 2.0. На ноуте:
   ```
   for d in /sys/bus/usb/devices/*/; do [ "$(cat $d/idProduct 2>/dev/null)" = 8812 ] && \
     echo "$d speed=$(cat $d/speed) bcdUSB=$(cat $d/version) power=$(cat $d/bMaxPower)"; done
   ```
   A/B на одном адаптере: плохой кабель → `speed=480 bcdUSB=2.10 500mA`, родной →
   `speed=5000 bcdUSB=3.00 800mA`. (USB 3.0 устройство на USB 2.0 кабеле честно
   рапортует `bcdUSB 2.10` — это не значит, что оно «само USB 2.0».)

**Про порты девкита.** Все четыре Type-A Orin Nano Developer Kit — USB 3.2, но каждый
разъём внутри раздвоен: контакты USB 2.0 идут на Realtek-хаб `1-2.x` (Bus 001, 480M),
SuperSpeed-пары — на Realtek-хаб `2-1.x` (Bus 002, 10000M). Это один комплект разъёмов,
«переткнуть в USB 3.0 порт» ничего не меняет.

**С родным кабелем на Jetson** энумерация проходит с первой попытки — но адаптер всё
равно садится на **USB 2.0** (`1-2.3`, 480 Мбит, `bcdUSB 2.00`, 500 мА). Это норма:
RTL8812AU стартует в USB 2.0-режиме, в USB 3.0 его переключает драйвер
(`rtw_switch_usb_mode=1`), по умолчанию — нет. 480 Мбит ≫ радиоканал, менять незачем.

**Кабель под габариты дрона.** Родной — длинный, штекер прямой. Нужен **короткий
угловой USB 3.0 micro-B** (такие делают для внешних HDD, 0.2–0.3 м, четыре варианта
загиба; искать «USB 3.0 Micro B 90 degree 0.3m») либо угловой переходник USB 3.0
micro-B + короткий USB 3.0 кабель. Компактный USB 2.0 кабель годится только с
**отдельной подачей 5 В** на адаптер (Y-кабель / BEC), по USB — только данные.
Активный хаб на дроне — лишний вес и точка отказа.

## 2. Драйвер

В ядре борта `5.15.185-tegra` драйвера нет: in-tree `rtw88_8812au` появился в 6.13
(на ноуте с 6.x он подхватывается сам), каталога `realtek/rtw88` в модулях Jetson нет
вовсе. Устройство энумерируется, интерфейс `1-2.3:1.0` без драйвера, `wlx…` не
появляется.

Ставится **`distro/usr/local/sbin/setup-rtl8812au.sh`** — DKMS-сборка
[morrownr/8812au-20210820](https://github.com/morrownr/8812au-20210820) @ `4722250`
(2026-08-20), пакет `rtl8812au/5.13.6-23`, модуль **`8812au`**, исходники на борту
`/opt/src/8812au-20210820`, опции — `/etc/modprobe.d/8812au.conf` (копия installer'а
лежит в `distro/etc/modprobe.d/`, источник правды — она).
```
cd distro && ./deploy.sh -X /usr/local/sbin/setup-rtl8812au.sh usr etc
```
Ставит `dkms build-essential bc git`, клонирует, `install-driver.sh NoPrompt`,
`modprobe 8812au`. Сборка на Orin Nano ~3 мин. Идемпотентен (installer снимает старую
dkms-версию). **После обновления ядра — запустить снова.** Заголовки ядра на борту
есть (`nvidia-l4t-kernel-headers`), интернет нужен (Wi-Fi/Ethernet).

Результат 2026-09-21: `rtl8812au/5.13.6-23, 5.15.185-tegra, aarch64: installed`,
интерфейс `wlx00c0cabacab9`, через NetworkManager видит сети в обоих диапазонах
(`TP-Link_6611` 100 % @2457 МГц, `Sheny1` @5180 МГц).

## 3. Причуды драйвера (не баги)

| Наблюдение | Что на самом деле |
|---|---|
| `iw dev wlx… scan` пуст | Out-of-tree драйвер сканирует только по триггеру. Смотреть `nmcli dev wifi rescan ifname wlx… && nmcli dev wifi list ifname wlx…` |
| `txpower -100.00 dBm` | Фикция, драйвер мощность не рапортует |
| **Диод не горит** на Jetson, на ноуте горит | `rtw_led_ctrl=1` («normal blink»): тёмный, пока адаптер **не ассоциирован**; мигает при скане и трафике. На ноуте `rtw88` зажигает диод сразу при включении радио. Хочется всегда — `rtw_led_ctrl=2` в `8812au.conf` (через distro). На дроне полезнее «по трафику» — индикатор живого линка |
| `rtw_power_mgnt=2` | Дефолт модуля = **maxPS**, агрессивное энергосбережение (в `8812au.conf` не прописано). Для линка с дроном — задержки и провалы на простое. **TODO:** `rtw_power_mgnt=0` в опциях, одним коммитом с профилем NM |

Все параметры: `ls /sys/module/8812au/parameters/`, значения —
`grep . /sys/module/8812au/parameters/*`.
