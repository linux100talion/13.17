Идея пилота после cmd/10: «ветер (трим и направление) — глобальный объект, а не передача между
ярусами». Сделано: `control_pkg/domain/control/wind_trim.py` — `WindTrim(x, y, learned, imax)`,
мировой вектор в ВАЛЮТЕ PWM КАНАЛОВ (pitch_off, roll_off со знаками стабов) в раме ENU по курсу AHRS
`att_yaw`; (pitch_off, roll_off) крутится как вектор тела (вперёд, влево) — физический наклон
(−p, −r) с поворотом коммутирует. API: channel(psi)/set_channel/channel_axis/set_channel_axis/reset.
Подключение: `StationFrame(wind=…)` — trim_body/set_trim_body(axis, value, sign=osign) ходят в него,
reset() рамы ветер не трогает; `DpVins.wind` — читает/пишет по att_yaw (НЕ vins_yaw), `_trim_armed`
= property над wind.learned, seed_trim/reset_trim — no-op; демпфер на входе при wind.learned не
проходит первый брейк с ki_trim, а после своего первого брейка ставит learned. Нода создаёт
`self.wind` (imax = max(dpvins/roll/pitch imax)), `build_stabilizers(cfg, spec, wind)` /
`build_vins_stab(cfg, wind)` / `compile_mission(..., wind)`, сброс на фронте арма. Ручка
`wind_trim` (BS_WIND_TRIM, дефолт 1); 0 = старые пути бит в бит (тесты legacy без wind зелёные).

**Why:** у демпфера трим жил в StationFrame, у DpVins — в раме VINS, посев только 0→1 и только на
девственный (провал 46 м cmd/3 — читал идле-копию); 1→0 DpHold.enter сбрасывал раму → захват
ветра заново первым брейком (2–3 с сноса на каждом переключении), после LOITER тоже; перерождение
VINS обнуляло трим DpVins, хотя ветер физический. Один объект убирает класс ошибок шва и это
кусок единого демпфера ([[unified-damper-signal-adapter]]).

**Регресс первого полёта 185004** («на DpVins стрелка ветра пляшет после разворота»): по bag трим в
мире качался ±40 PWM с T≈4 с в висении на ярусе 1 (компас HUD — относительно носа, разворот ни при
чём) — DpVins входил в ярус с wind.learned=False (флаг ставили только первый брейк демпфера / первый
гвоздь DpVins), т.е. с фазой захвата ki_trim 60, которую раньше снимал посев (armed на входе). ФИКС (по
предложению пилота — «оставить как было, флаг ставить на переходе яруса, чтобы поведение DpHold не
изменилось»): WindTrim.handoff() = если |трим| ≥ 1 PWM (граница посева) → learned; зовут
Freefly._ladder_apply на СМЕНЕ яруса (не на первом применении стека) и SoftLand._enter_alt;
enter() стабов флаг не трогают. Тест ladder §15. Попутно: на ярусе 0 сразу после разворота на 60–180° трим тоже
прыгает (73 → 16 PWM за 2 с) — фантом IPM на рыскании, не WindTrim, открыто.

**How to apply:** ПОЛЁТОМ НЕ ДОКАЗАН (фикс known — тоже) — проверить переключениями 0↔1↔2: стрелка ветра непрерывна,
без сноса на входе в ярус в обе стороны, после LOITER демпфер держит сразу; A/B бит в бит на bag
одного яруса — BS_WIND_TRIM=0 против 1 у демпфера должны совпасть (хранилище эквивалентно), у
DpVins расхождение только на разнице att_yaw/vins_yaw (1–3°). LOITER ветер (EKF drag) пока не
подмешивается — естественный следующий шаг: в ярусе 2 обновлять WindTrim из EKF. Тесты
test_wind_trim.py, test_mission_plan. Связано: [[dpvins-wind-trim-learn]], [[dphold-vs-dpvins-gusts]].

**ВОЗВРАЩЁН 2026-09-06 вечером (не закоммичен на момент записи; кандидат `profiles/wind/trim.txt`, A/B
`cmd/11/11.sh` с `WT=0|1`)** по вопросу пилота «почему нельзя просто расшарить два числа и ставить флаг
на передаче». Улика отката загрязнена: на DpHold «стрелка крутится» = капкан ω_z ([[ipm-wz-bias-trap]],
закрыт 56dcb15), а на DpVins нашёлся ДЕФЕКТ ПЕРВОЙ ВЕРСИИ — ДВА ПИСАТЕЛЯ: `handover.vins_stabs` держит
композит DpHold в стеке яруса 1 (keep = стабы с yaw, а у DpHoldM оси roll+pitch+yaw → весь композит;
выход перезаписан DpVins), и его оси roll/pitch каждый кадр писали свой И-член (ошибка IPM против
СОБСТВЕННОГО гвоздя тени) в общий трим параллельно с DpVins — два интегратора на одном векторе; это
объясняет качание трима ±40 PWM T≈4 с в висении яруса 1 (185004) не хуже гипотезы learned=False.
Добавки (`wind_trim.py`): (1) ВЛАДЕЛЕЦ `owner` — пишет/observe/mark_learned только активный ярус (рама
демпфера либо DpVins; назначает `handover` в enter стаба; вызов без подписи = стенд), тень читает;
(2) СНИМОК УСТОЙЧИВОГО HOLD — `observe(now, steady, who)` каждый тик активного яруса (композит DpHold
`_wind_steady`: обе оси станции в HOLD, не защёлка/анти-виндап, кадр свеж ≤ stale, |IPM v| < steady_v И
VINS (если valid и свеж 0.5 с) < steady_v; DpVins: гвоздь, обе станции без брейка, стики центр, обе
оси учатся, |VINS v| < steady_v И IPM (если ipm_ok) < steady_v), серия ≥ `wind_steady_sec` 3 → снимок
(следит, пока серия жива); `handover(now, who, force_learned)` идемпотентен по тику (композит + DpVins
входят одним тиком): устойчив сейчас (серия набрана, наблюдение ≤ 0.5 с — после LOITER протухает) →
живой L; иначе снимок S + learned; снимка нет → живой как есть N (= старый посев; ноль при ki 8 = унос
трим/ki 17 м на ветре 10 — поэтому НЕ ноль); DpVins на входе всегда learned (иначе ki_trim 60 до гвоздя
раскачивал T 7 с); статус `wt=<S|s|->/<L|S|N>/<снимок PWM>/<выучен>` во всех ярусах; (3) стрелка HUD
`wind_arrow_fade`: 0 ниже 8 PWM (подпись `WIND calm`), 1 с 15, линейно, только тримы (EKF в LOITER как
есть). Ручки `BS_WIND_STEADY_SEC` 3 / `BS_WIND_STEADY_V` 0.5. Тест `test_wind_trim.py` 48 проверок.
Полётом НЕ доказан — протокол в cmd/11/README.txt (тот же сценарий на обоих плечах, судить по wt= на
фронтах tier=, сносу на входе, первому брейку после LOITER, стрелке на scene_hud.mp4). Открыто: формула
силы HUD 10·√(PWM/100) завышает слабый ветер (стенд PWM≈100·(v/10)^1.18); ветер EKF в LOITER в объект
не подмешивается.
