Замер по 6 bag'ам (3 реплея lv_flight2 при ветре 5 от 2026-08-23 + 3 полёта
2026-08-22). Инструмент: `src/lab/phase_stats.py` (внутри p1317_nav).

Фазы реплеев (sim-с): prearm 1-3; **EKF/GPS-прогрев → арм 43-44 (самая
стабильная и длинная обязательная фаза)**; взлёт до отрыва 5.9; **init VINS
0.3-2.1 после отрыва** (вертикальный климб в текстурной сцене инитит монокуляр
почти сразу; контрпример 232043 — непрерывный yaw, /odometry НЕТ во всём bag);
зрелость+свап до READY **20-62 с — ПЛАВАЕТ**; латч LOITER после CH6: мгновенно
(0.0-0.1) если гейт уже открыт, 12-16 с если щёлкнули до READY. Итого
старт→LOITER 101-116 с.

**Почему READY плавает — ДОКАЗАНО (n=8 за 2026-08-23):** гейт зрелости —
СЧЁТЧИК сообщений (ripe_n=600), длительность фазы полностью определяется
частотой /odometry, другой дисперсии НЕТ: 6 прогонов @10.0 Гц → READY за
59-62 с; 2 прогона (141554, 210157) @14.7 Гц (dt=0.068) → READY за 21-24 с.
**«Мода 14.7 Гц» РАЗГАДАНА (2026-08-24, код форка + bag'и 041803/210723):**
freq-контроль feature_tracker — среднее по ДЛИННОМУ окну с round():
публикует пока round(count/elapsed)≤10, окно сбрасывается только при
avg∈(9.9,10.1) — траектория прилипает к 10.49 и сброса не бывает → штатный
выход 10.4-10.5 Гц (не 10), кванты dt=0.102 («пропусти 2 кадра») и 0.068
(«пропусти 1»; ~1.1 шт/с есть и в нормальных прогонах). Любой период, где
камера/трекер шли медленнее 10.5 Гц (CPU-затык на старте стека; паузы ≤1 с
discontinuity-чек НЕ ловит), копит «долг» среднего — после восстановления
гейт открыт, пока долг не выплачен: трекер пропускает каждый 2-й (14.7) или
каждый кадр (29.5). Быстрые прогоны = выплата долга на всё окно зрелости
(600 сообщ. за 21-24 с ≈ 27 Гц ⇒ долг ~360 сообщ. ≈ полминуты полускорости
до init). Мода для VINS безвредна, но гейт-СЧЁТЧИК превращает её в обнуление
запаса зрелости (физика масштаба ~21 с). **Гейт ПЕРЕВЕДЁН на sim-время потока и ДОКАЗАН серией 3×LV=2 (2026-08-24,
прогоны 050600/050901/051212, все exit 0):** ripe_sec=30 (BS_RIPE_SEC,
_vins_ripe в bootstrap_node: время от первой одометрии vins_first_sim + пол
по счётчику vins_min=300; GPS-kill = ripe_sec+15 с). ripe_swap стал
30.3/30.3/31.3 с (разброс 1.0 с вместо 20-62), total старт→LOITER 65-68 с;
CH6 сценария теперь находит гейт открытым — латч LOITER мгновенный.
Слепое пятно (как у счётчика): рестарт VINS в полёте гейт не видит —
ловит vins_fresh.
**2-я ступень — ДЕТЕКТОР (ripeness.py), доказан серией 3×LV=2 (053321/
053630/054018, все exit 0): ripe_swap 8.9/10.6/9.5 с** (res 0.06-0.11,
ratio 0.93/1.02/1.18; пол пути 8 с). Детектор = residual «поза/скорость»
по HEADER-штампам (⚠️ по времени прихода residual врёт вверх — прогон
052917: 0.24 при поле 0.05-0.10, зрелость открыл таймер = страховка
работает) + вертикальный ratio VINS/rel_alt на климбе. res/rat видны в
HUD (мелкая строка под баннером). total не сжался (~64-66 с): CH6
сценария щёлкает по фикс-таймингу — живой пилот с HUD заберёт эти ~20 с.
Финальная серия 205720/210157/210723 (страховка дизарма v2 на борту, ни разу
не понадобилась): total старт→LOITER 96-112 с; у 210723 дизарм прошёл при
залипшем баро 2.8 м — залипание высоты НЕ ВСЕГДА блокирует детектор посадки.

**Слепота сценария:** в 2 из 3 реплеев CH6-центр щёлкается по фикс-таймингу
СЦЕНАРИЯ на 12-16 с РАНЬШЕ READY (борт ждёт в ALT_HOLD, LOITER подхватывается
сам при открытии гейта). Идея: якорь `wait_ready` в joy_replay по
/mission/status — реплей станет ждать гейт, как живой пилот с HUD.

Прогрев стека ДО лётной ноды (mavros.log, wall): MAVROS connect → Raw IMU
+3 с → EKF3 IMU init +4 с → tilt/MAG align +6 с → origin set +23 с →
**is using GPS +45 с**. «Прогрев IMU» отдельной полётной фазой не существует —
он внутри старта стека; ekf_gps-фаза ноды (43-44 с) ждёт ровно хвост этого
GPS-прогрева. Связано: [[openhd-debug-hud]], [[joystick-replay-series]].
