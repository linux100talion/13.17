Серия LV (штатный ArduPilot Loiter на EKF-от-VINS) закрыта 2026-08-19, ветка
`nn2_c3_laptop_vins`, коммиты e36c53b…8b94f66. Ранбук — `docker/sim/doc/old/
laptop_move.md` §3 (доки переехали в doc/old 2026-08-21); актуальное описание
перехода в LOITER — `docker/sim/loiter.md`.

**Пилотный freefly-LV ДОКАЗАН 2026-08-20** (6-й прогон, W10, GPS заглушен):
центр CH6 → латч <2.5 с, 0 отказов/EKF-событий, hands-off 34 с — ср. 0.12 м
(лучше скриптового LV5: 0.85 м). Путь: 5 слоёв, каждый вскрыт данными и
закоммичен (см. пункты ниже, полёты №2-№5).

- **Доказано:** LOITER латчится и держит 40 с на чистом VINS (GPS заглушен) —
  прогон LV5, `ИТОГ: LOITER_DONE`. A/B: Loiter полётника 0.85 м ср. отклонения
  против **0.07 м у VinsHold** на том же VINS (×10) — это блуждание оценки EKF,
  не слабость Loiter; VinsHold ест сырую VINS-позу.
- **Обязательные ручки LV-профиля:** `VISO_TYPE 1` в `sitl-extra.parm`
  (раскомментировать; без него «Loiter failed: requires position») и
  `BS_VINS_MIN=300` (свап хэндовера на VINS моложе ~2 с от init посреди
  манёвра = ускоряющийся разгон при честной опоре — LV6; дефолт 40 не переигран, n=1).
- **⚠️ VISO_TYPE живёт в EEPROM** (записан param_set'ом 2026-08-19): eeprom
  СИЛЬНЕЕ `--defaults` — parm-строка решает только для параметров, которых в
  eeprom нет (994e471: freefly с parm=1 отлетал с фактическим 0, FCU не получил
  ни одной vision-позы). Переключать VISO_TYPE — pymavlink param_set + ребут
  SITL; parm-строка — документация желаемого состояния, не механизм.
  **Стенд запаркован 2026-08-21**: eeprom в GPS-профиле (VISO_TYPE=0,
  SIM_GPS1_ENABLE=1, EK3_SRC1_POSXY/VELXY=3, через sitl_lv_profile.py 0),
  контейнеры остановлены (compose stop). Поднимать: `make up && make wait`
  или сразу `bash src/lab/freefly_lv.sh` — обёртка сама готовит eeprom.
- `SIM_GPS1_ENABLE` самовосстанавливается очередью ноды (3ef2eb1), но ТОЛЬКО
  в прогонах с `BS_GPS_DISABLE` — после LV-прогона перед обычным прогоном
  проверить/вернуть 1 (последний LV-полёт глушит GPS, eeprom персистится).
- **Ручной pymavlink-шаг между профилями АВТОМАТИЗИРОВАН 2026-08-21**: обёртка
  `src/lab/freefly_lv.sh` (LV=0/1) перед атомарным прогоном готовит eeprom
  через `docker/sim/scripts/sitl_lv_profile.py` (pymavlink tcp:5762 в контейнере
  simulator): LV=1 → VISO_TYPE=1; LV=0 → VISO_TYPE=0 (с 1 без vision-фида не
  армится — «VisOdom: not healthy», ARMING_CHECK 0 не снимает) + возврат
  POSXY/VELXY=3, SIM_GPS1_ENABLE=1. Применяется на рестарте стека внутри
  прогона. Оба эталонных env-блока и разбор их соотношения — `docker/sim/Q.txt`.
- Механизмы, рождённые серией: токен `loiter<t>` (шаг `LoiterHold`), freefly-центр
  CH6 = Loiter (`BS_FF_LOITER=1`, в полёте не испытан — только офлайн-гейты),
  шаг `ekf_warmup` (арм только с позицией EKF), `_calm_phase` для свапа
  EK3-источников, порядок хэндовера `keep+[vins]` (композит [[vins-solver-fix]]).
- **Полёт №2 2026-08-20: feature_tracker умер на кадре холодного старта v4l2**
  (rowRange-assert СКВОЗЬ гвард размера de17c71) → VINS без фич весь полёт,
  odom=0, freefly-центр честно отказал. Фиксы: try/catch всего img_callback в
  форке (**4c826bd; вместе с de17c71 НЕ ЗАПУШЕНЫ на GitHub — в контейнере нет
  кредов, запушить с машины с доступом**) + nav_up.sh теперь пересобирает
  feature_tracker/vins_estimator инкрементально на каждом старте стека (ef8d241;
  раньше форк-фикс не попадал в бинарь до ручного nav-rebuild).
- **Полёт №7 2026-08-21: разовый якорь кадра ловит ХУДШИЙ момент — юный VIO.**
  Латч был идеален (VISP−XKF1 = 0.11 м), но за следующие 8 с юный VINS
  (ratio ×10, полёт №3) при активном пилотировании в W10 наврал 4 м, офсет
  не обновлялся → своп POSXY→6 через минуту получил vision за гейтом →
  «variance: position lost» через 8 с ПРИ ЖИВОМ GPS, stopped aiding, вечный
  «Loiter requires position». Глушение GPS проскочило в окно (гейт свежего
  local_position проверяется раз в 2 с — поза ещё публиковалась). Пилот всё
  делал правильно; №6 повезло (спокойнее летал в юной фазе). Диагностика:
  дельта VISP-vs-XKF1 по времени (0.11→4.0 м) + XKF3-инновации (6 уникальных
  из 90 после свапа = голодание). Фикс: ray_tracer теперь СЛЕДИТ за якорем
  пока нет засечки NN1 и EKF свеж — расход >1 м = жёсткая подтяжка, меньше =
  дожим τ=5 с (симуляция: худший расход ≤1 м, на свапе 0.1 м); после свапа
  EKF следует vision → слежение затухает само. nav_pkg пересобирается в
  nav_up.sh на каждом старте — фикс доезжает без ручного rebuild.
  **ДОКАЗАН полётом №8 2026-08-21**: одна жёсткая подтяжка на юном транзиенте
  (расход 1.20 м через 0.2 с после латча), дельта VISP↔XKF1 0.00-0.20 м ВЕСЬ
  полёт, LOITER с одного захода без отказов, 0 EKF-событий, max SV=0.06
  SP=0.24, ~7 минут LOITER на чистом VINS с убитым GPS. Пилотский нюанс:
  центр до зрелости пары (odom<600) честно даёт «LOITER не готов» → ALT_HOLD;
  после установки EK3_SRC1_* латчится сам.
- **Полёт №5 2026-08-20: скорость IPM в ветре — фантом, травит EKF.** Якорь
  кадра сработал (offset 7.6 м), фьюжн позы пошёл, но в миг `VELXY→6`
  скоростной варианс-ратио 1.72: IPM слал 1.5-2.6 м/с при истинных 0.1-0.2
  (VISV vs gt; деротация на порывах W10) → циклы EKF Failsafe → FCU сам в
  LAND, наш ре-ассерт воевал. Фикс 718f019: extern-профиль ставит **VELXY=0**
  (EKF ведёт чистой позой VINS, скорость выводит сам; IPM-скорость — только
  'integral'-профилю и для health VisOdom при арме); freefly-центр уважает
  failsafe-LAND (не ре-ассертит, тумблер вверх забирает борт). LV5 без ветра
  фантома не видел — обе скорости ~0.
- **Полёт №4 2026-08-20: КАДРЫ VINS и EKF расходятся — extnav-фьюжн не
  начинается.** Мир VINS рождается в точке init (в воздухе, куда пилот улетел),
  кадр EKF — от арма: офсет 9.6 м → каждое vision-измерение за инновационным
  гейтом EK3 (рантайм-смена EK3_SRC1_POSXY ресета позиции НЕ делает) → фьюжн
  голодает, «variance: position lost» ещё при живом GPS. Скриптовые LV работали
  СЛУЧАЙНО: sk-шаттлы возвращают борт к дому (LV5: офсет 0.2 м — фьюжн чист).
  Фикс cd26d22: ray_tracer при первой одометрии защёлкивает offset=EKF−VINS по
  живой local_position (без EKF-позы — offset 0, боевой бут как раньше). На
  боевом борту та же мина. Диагностика: VISP-vs-XKF1 в dataflash + счётчик
  уникальных значений XKF3-инноваций (замёрзли = фьюжна нет).
- **Полёт №3 2026-08-20: EKF-свап на незрелом VINS валит фьюжн** — очередь
  свапнула EK3 на extnav при VINS ~3 с от init (гейт был odom>50): перемещение
  VIO врёт до ×10 первые ~20 с (bag: ratio 0.11→10.0→1 к ~21 с ≈ 550-600 odom),
  «EKF variance: position lost» через 3 с после глушения GPS, позиция потеряна
  до посадки. Стики пилота были В ЦЕНТРЕ — «спокойные стики» не гейт (ветер+
  демпфер сами создают скорость). Фикс 77d5e39: без спокойной фазы 6-пара ждёт
  odom > max(600, 2×vins_min), глушение GPS ещё +150 odom (EKF обкатывается на
  extnav при живом GPS; развал → local_position тухнет → GPS не глушится).
- **Пилотный freefly-LV 2026-08-20 повторил LV4 в ручном виде**: пилот заармил
  на 17-й секунде после бута (freefly не имел ekf_warmup) → EK3 не начал aiding,
  в воздухе не стартует → const_pos весь полёт, LOITER refused при живых
  VISP/VISV (фикс VISO_TYPE подтверждён dataflash'ем). Фиксы: ekf_warmup вшит
  во freefly при ff_loiter (газ прижат — руддер-арм невозможен до позиции EKF);
  гейт глушения GPS требует свежий local_position (не добивать полёт без
  aiding); честный WARN «FCU не латчит — фактически ALT_HOLD» через 5 с.
