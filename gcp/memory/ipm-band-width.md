A/B на кадрах `docker/sim/output/joystick/yaw/swing/1/bag` (боевой `FlowEstimator`,
лётный конфиг, высота = EKF z − z₀ латча, углы — истина Gazebo), 1184 кадра воздуха:
- yhalf 1.0 / 2.0 (полёт) / 3.5 м → шум приращения пути за кадр fwd 7.4/7.2/7.2 мм,
  lat 6.6/6.4/6.4; попарная разница приращений 0.2 мм (corr +1.00) — пиксельная
  часть ≈3% ошибки, медиана по 120–350 фичам уже сошлась. Лимит фич (200→400) — тоже 0.
- длиннее/дальше: 3–6 → 3–9 → 3–12 → 6–9 м: fwd 7.2 → 8.5 → 9.8 → 9.5 мм,
  vlat corr 0.71 → 0.64 → 0.57 → 0.36; чувствительность к Δpitch 631 → 747 → 830 →
  1078 мм/рад (∝ h/sin²α). «Далеко нельзя» — подтверждено числом.
- что реально шумит: Δpitch −630 мм/рад (R² 0.42 fwd) = остаток ~8% от сырой
  чувствительности ≈ тайминг «штамп кадра ↔ угол» (кадры квантованы 4 мс /clock;
  в полёте ATTITUDE 12.5 Гц — хуже); lat: Δroll −340, ω_z +127 мм/рад (утечка X·dψ).
- побочно: путь меряется 0.89–0.90 от истины на всех вариантах при palt/AGL 0.998 —
  постоянный масштаб (кандидат: смещение наклона камеры ~1.5–2°), не шум.
- yhalf/x0/x1 — только ctor-аргументы класса, в config.py/BS_* ручки нет; при
  yhalf 3.5 уже 43% кадров с углом полосы за кадром (чёрные клинья в варпе).
- у демпфера ошибка скорости 0.2 м/с — это лаг (win 0.3 + vel_tau 0.4), а шум
  наклона МНК от 7 мм/кадр ≈ 0.03 м/с: окно можно резать до ~0.15 без упора в пиксели.

**Why:** вопрос «взять полосу пошире?» возникает по картинке scene_ipm.mp4 — ответ
доказан стендом, не переспрашивать. Стенд — `src/lab/ipm_band_ab.py` (в таблице
`src/lab/CLAUDE.md`); бегает на ХОСТЕ без контейнера (venv cv2 + jazzy, bag из sqlite).
⚠️ высоту брать латчем EKF z, не `palt=` из /mission/status (шаг 0.1 м → ложные выбросы).
**How to apply:** ширину полосы не трогать; рычаги сигнала — синхронизация углов с
кадром и ближняя полоса (наклон камеры), не геометрия ширины. См. [[damper-low-alt]],
[[sim-ground-texture-blind]].
