Впрыск команд пилота/скрипта/NN2 в `DpPitchHold` сделан интегратором уставки
(`_FlowDamper1D._cmd_mode`: `rate` для крена/рыскания, `pos` для тангажа):
`sp += c_fwd·cmd_gain·fdt; err = kf_logs − sp`, D-член вычитает скорость уставки.
`pitch_cmd_gain` меряется в **log/с при полном стике** = `v_max · 0.0145`.
Дефолт 0.0 — команда не проходит, поведение всех калибровочных серий не изменилось.

Прогон `L1_mvfwd` (30.07.2026, `climb3,hover10,mv_fwd5,hover20,land`, gain 0.048):
механизм подтверждён — скорость уставки ровно 0.0144 log/с (0.99 м/с), ошибка до
уставки ушла с +1.30 до −0.30 м, зрение шло за уставкой. НО борт физически поехал
НАЗАД на 1.5 м: гейн канала зрения внутри одного полёта гулял 0.35 / 1.81 / 1.46 по
сегментам, и на манёвре канал наврал ~+0.6 м/с ложного «вперёд» — контур честно
отследил врущий датчик.

**Why:** механизм впрыска больше не блокер; блокер — метрическая достоверность
`kf_logs`. Командовать метрами нельзя, пока гейн канала не станет постоянным.

**How to apply:** новые попытки «полететь по команде» бессмысленны до починки канала
(`ToDo3.md` §3: записать `/image_mono` в бэг и переиграть оба потока кадров). Уставку
всегда смотреть в `/flow_dbg5` (x=уставка, y=ошибка, z=скорость) — из телеметрии она
не восстанавливается. Связано: [[no-edit-scripts-midrun]], [[always-upload-video]].
