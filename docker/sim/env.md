# `env.default` / `.env` — профиль стека и прогонов

Профиль — строки `KEY=VALUE` — живёт в ДВУХ файлах рядом с `docker-compose.yml`:

| Файл | В git | Роль |
|---|---|---|
| `env.default` | ✅ | **ЭТАЛОН проекта**: боевые дефолты (LV=2, SF-мастер, fine-мир) едут на все боксы |
| `.env` | ❌ (`.gitignore`) | **рабочая копия бокса**: её читают compose и freefly_lv; машинные правки — тут |

`.env` при отсутствии создаётся копией `env.default` **автоматически**:
таргет `ensure-env` прицеплен к `make build`/`up`/`restart-all`/`fresh-start`,
тот же посев делает `freefly_lv.sh` перед чтением дефолтов. Свежий клон летит
боевым профилем без ручной возни; существующий `.env` НИКОГДА не перетирается.

**Куда писать правку:**

- меняешь дефолт ПРОЕКТА (для всех боксов) → `env.default` **и** свой `.env`
  (автопосев существующий `.env` не обновляет);
- подгоняешь под конкретную машину (пути, GPU, свой мир/ветер) → только `.env`.

## Кто читает `.env`

1. **docker compose** — классически: интерполирует `${KEY:-дефолт}` в
   `docker-compose*.yml` (пути bind mount, env контейнеров). Значение доезжает
   до контейнера только при его **СОЗДАНИИ** (`fresh-start`; `restart-all` env
   не перечитывает). `freefly_lv.sh`/`capture_scene.sh` делают fresh-start
   сами — для прогонов серии ничего специально перезапускать не надо.
2. **`src/lab/freefly_lv.sh`** — как слой дефолтов ПРОФИЛЯ ПОЛЁТА (с 2026-08-26):
   в начале скрипт проходит `.env` и экспортирует строки `KEY=VALUE`, **только
   если переменная не задана снаружи**. Так голый `bash src/lab/freefly_lv.sh`
   летит боевым профилем, а любой ключ переопределяется как раньше:

   ```
   env снаружи (LV=1 bash ...)  >  docker/sim/.env  >  дефолт скрипта (LV=1)
   ```

   Скрипт печатает, что взял: `freefly_lv: дефолты бокса из docker/sim/.env:
   ...` — в логе прогона видно, какие ключи пришли из файла, а какие
   переопределены снаружи.

## Что ещё сюда можно класть

Любой ключ, который хочется сделать постоянным дефолтом (бокса — в `.env`,
проекта — в `env.default`):

- **Ключи compose** (см. `${...}` в `docker-compose*.yml`): `SPAWN_POSE`
  (постоянная точка старта — шесть чисел или имя пресета `spawn_save.py`, см.
  `spawn.md`), `WIND_SPD` / `WIND_DIR_DEG` / `WIND_FACTOR`, `CAMERA_W`/`CAMERA_H`,
  `VISION_POSE_SOURCE`. Применяются на fresh-start.
- **Ключи freefly_lv** — всё, что скрипт принимает через env: `BS_*`
  (пробрасываются в контейнер автоматически, см. `capture_scene.sh`), `WIND_SPD`,
  `RES`, `GDRIVE_UP`, `MP4`, `KEEP_BAG`, `HUD_MP4`, `TOPICS_EXTRA`...

Правила разбора в freefly_lv: пустые строки и `#`-комментарии пропускаются,
ключ — валидный идентификатор (`A-Za-z0-9_`, не с цифры), парные кавычки вокруг
значения снимаются (как делает compose). Значение с пробелами (например,
`SPAWN_POSE="x y z r p y"` или `TOPICS_EXTRA="..."`) — в кавычках.

## Грабли

- **`restart-all` env не перечитывает** — ключи compose доезжают только при
  пересоздании контейнера (`fresh-start`). Скрипты серии делают его сами.
- **Обновлённый `env.default` на старом боксе сам не применится** — автопосев
  существующий `.env` не трогает. Перенести строку в `.env` руками (или
  удалить `.env` и дать пересеяться — потеряв локальные правки).
- **После автопосева на новом боксе** проверить два машинно-зависимых ключа:
  `VINS_SRC` (где лежит форк) и `CUDA_ARCH_BIN` (арка GPU) — баннер посева
  об этом напоминает.
- Ключи, которые НЕ ест ни compose, ни freefly_lv (например, `make`-переменные
  типа `CPU`), из `.env` никуда не доедут — их по-прежнему давать в команде.
