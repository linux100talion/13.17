# `env.default` / `.env` — профиль бокса; `cmd/` + `profiles/` — профиль полёта

Ручки прогона собираются из СЛОЁВ. Сверху вниз, верхний перекрывает нижние:

```
1. профили src/control/profiles/*/*.txt — собирает load.py, вызывает cmd/<имя>/<имя>.sh
2. env снаружи             (WIND_SPD=5 LV=1 bash cmd/bl/bl.sh …)
3. docker/sim/.env         (локальный профиль бокса; эталон — env.default)
4. дефолты freefly_lv.sh   (LV=1 и т.п. — если ничего выше не задало)
5. дефолты ноды            (mission_pkg/config.py через bootstrap_arch2.sh)
```

Слой 1 — `eval "$(python3 src/control/profiles/load.py …)"` под `set -a`
(с 2026-09-07; include + дельта, дубль ключа между профилями = ошибка), поэтому
для СВОИХ ключей профиль перекрывает и внешний env, и `.env`:
`BS_ROLL_RATE_KP=50 bash cmd/bl/bl.sh` полетит с 90 из `dphold/baseline.txt`.
С 2026-09-07 в профилях ВСЕ `BS_*` ноды, включая миссию/пилота (`mission/`) и
легаси (`legacy/`) — под `cmd/*` слои 3–5 для `BS_*` затенены целиком. Env
снаружи сильнее профиля только там, где скрипт cmd сам пишет `${X:-…}`
(`WIND_SPD`, `WIND_GUST` в `bl.sh`), и для ключей вне профилей (`LV`, `RES`,
`KEEP_BAG`, аргументы реплея `BS_REPLAY_*`…). `freefly_lv.sh` применяет строку
`.env` ТОЛЬКО к незаданной переменной — что пришло из профиля или env снаружи,
он не трогает.

Кто за что отвечает:

| Слой | Где | В git | Что там живёт |
|---|---|---|---|
| профиль ПОЛЁТА | `src/control/profiles/<ярус>/*.txt` + `cmd/<имя>/<имя>.sh` | ✅ | ВСЕ ручки стабилизаторов `BS_*` по ярусам (демпфер, DpVins/VinsHold, опора VINS и гейт здоровья, LOITER, WindTrim); `cmd/bl/bl.sh` = текущий baseline, `cmd/<имя>/` = кандидат, `cmd/history/` = отлетавшие. Конвенция — `cmd/README.txt`, формат/слои — `src/control/profiles/README.md` |
| профиль БОКСА | `docker/sim/.env` (эталон `env.default`) | `.env` ❌ / `env.default` ✅ | машинное (пути, GPU, мир, ветер, спавн) и режим полёта вне стабилизаторов (`LV`, `BS_SF_MASTER`, `BS_LAND_JOY`, `WIND_*`, посадка, миссия) |

`.env` при отсутствии создаётся копией `env.default` **автоматически**: таргет
`ensure-env` прицеплен к `make build`/`up`/`restart-all`/`fresh-start`, тот же
посев делает `freefly_lv.sh`. Свежий клон летит боевым профилем без ручной
возни; существующий `.env` НИКОГДА не перетирается.

**Куда писать правку:**

- ручка СТАБИЛИЗАТОРА (`BS_*` из профилей) → файл-кандидат в
  `src/control/profiles/<ярус>/<имя>.txt` (копия baseline с изменённой строкой и
  гипотезой в шапке) + `cmd/<имя>/<имя>.sh` копией `cmd/bl` + README. В `.env`
  её писать бесполезно — профиль перекроет;
- дефолт ПРОЕКТА вне стабилизаторов (для всех боксов) → `env.default` **и**
  свой `.env` (автопосев существующий `.env` не обновляет);
- под конкретную машину (пути, GPU, свой мир/ветер/спавн) → только `.env`.

## Кто читает `.env`

1. **docker compose** — интерполирует `${KEY:-дефолт}` в `docker-compose*.yml`
   (пути bind mount, env контейнеров). Значение доезжает до контейнера только при
   его **СОЗДАНИИ** (`fresh-start`; `restart-all` env не перечитывает).
   `freefly_lv.sh`/`capture_scene.sh` делают fresh-start сами.
2. **`src/lab/freefly_lv.sh`** — как слой дефолтов (с 2026-08-26): в начале
   проходит `.env` и экспортирует `KEY=VALUE`, **только если переменная не задана**.
   Печатает, что взял: `freefly_lv: дефолты бокса из docker/sim/.env: …` — в логе
   прогона видно, какие ключи пришли из файла, а какие перекрыты сверху.
3. **`cmd/<имя>/<имя>.sh`** сам `.env` не читает — он source'ит профили, ставит
   `WIND_*` через `${X:-}` и `exec`'ает `freefly_lv.sh`, который читает `.env` как в п. 2.

Мета прогона `<RUN>.env` (пишет `freefly_lv.sh` в `output/joystick/<RUN>/`)
фиксирует, что реально доехало до ноды, независимо от слоя. Расхождение живого
прогона с профилями: `bash src/control/profiles/check.sh <RUN>.env`.

`BS_SF_MASTER=0 BS_PILOT=replay ... bash src/lab/freefly_lv.sh`.

## Что ещё сюда можно класть

Любой ключ вне стабилизаторов, который хочется сделать постоянным дефолтом
(бокса — в `.env`, проекта — в `env.default`):

- **Ключи compose** (см. `${...}` в `docker-compose*.yml`): `SPAWN_POSE`
  (постоянная точка старта — шесть чисел или имя пресета `spawn_save.py`, см.
  `spawn.md`), `WIND_SPD` / `WIND_DIR_DEG` / `WIND_FACTOR` / `WIND_GUST`
  (порывы поверх постоянного ветра, детерминированный профиль в sim-времени —
  спека в шапке `src/lab/wind_gust.py`, публикатор запускает `capture_scene.sh`;
  ⚠️ `cmd/bl/bl.sh` ставит свои `WIND_SPD`/`WIND_GUST` через `${X:-}` — env
  снаружи их перекроет, `.env` — нет, cmd отработает раньше),
  `CAMERA_W`/`CAMERA_H`, `VISION_POSE_SOURCE`. Применяются на fresh-start.
- **Ключи freefly_lv** — всё, что скрипт принимает через env и чего нет в
  профилях: `BS_MISSION`, `BS_PILOT`, бюджеты фаз, `BS_LAND_*`, `BS_FENCE`,
  `RES`, `GDRIVE_UP`, `MP4`, `KEEP_BAG`, `HUD_MP4`, `TOPICS_EXTRA`… (`BS_*`
  пробрасываются в контейнер автоматически, см. `capture_scene.sh`).

Правила разбора в freefly_lv: пустые строки и `#`-комментарии пропускаются,
ключ — валидный идентификатор (`A-Za-z0-9_`, не с цифры), парные кавычки вокруг
значения снимаются (как делает compose). Значение с пробелами (например,
`SPAWN_POSE="x y z r p y"` или `TOPICS_EXTRA="..."`) — в кавычках.

## Грабли

- **Ручку из профиля поверх `cmd/bl` через env не переопределить** — профиль
  перекрывает. Хочется один полёт с другим kp — копия `cmd/bl` в `cmd/<имя>/` с
  файлом-кандидатом, не `BS_X=… bash cmd/bl/bl.sh` (молча полетит по профилю;
  проверять по `<RUN>.env`).
- **`restart-all` env не перечитывает** — ключи compose доезжают только при
  пересоздании контейнера (`fresh-start`). Скрипты серии делают его сами.
- **Обновлённый `env.default` на старом боксе сам не применится** — автопосев
  существующий `.env` не трогает. Перенести строку в `.env` руками (или
  удалить `.env` и дать пересеяться — потеряв локальные правки).
- **Дубли `BS_*` в `env.default` и `baseline.txt` могут разойтись** — правишь
  baseline профиля, поправь и `env.default`/`.env` (или гоняй `check.sh` по
  голому прогону без cmd).
- **После автопосева на новом боксе** проверить два машинно-зависимых ключа:
  `VINS_SRC` (где лежит форк) и `CUDA_ARCH_BIN` (арка GPU) — баннер посева
  об этом напоминает.
- Ключи, которые НЕ ест ни compose, ни freefly_lv (например, `make`-переменные
  типа `CPU`), из `.env` никуда не доедут — их по-прежнему давать в команде.
