# Точка старта: «где сел — там и стартуем»

Прогон начинается не в центре площадки, а там и с тем курсом, где борт посадили
в прошлый раз. Точка сохраняется под именем один раз, дальше зовётся по имени.

```bash
# сохранить точку старта под именем (имя спросит, если не задать)
python3 src/lab/spawn_save.py docker/sim/output/joystick/lv1_joy_20260824_140447
#   под каким именем сохранить точку старта? among_trees
#   сохранено: docker/sim/output/spawn/among_trees
#     место:  x=-44.907 y=-31.536 z=0.245 м, курс -15.14°

python3 src/lab/spawn_save.py <прогон> among_trees   # имя сразу
python3 src/lab/spawn_save.py --list                 # что сохранено
python3 src/lab/spawn_save.py --show among_trees     # что внутри
```

Старт с этой точки:

```bash
SPAWN_POSE=among_trees bash src/lab/freefly_lv.sh
SPAWN_POSE=among_trees make -C docker/sim fresh-start
```

Разовый вариант, без сохранения имени:

```bash
SPAWN_FROM=docker/sim/output/joystick/lv1_joy_20260824_140447 bash src/lab/freefly_lv.sh
python3 src/lab/spawn_pose.py <прогон>    # просто напечатать SPAWN_POSE="..."
```

## Что и откуда берётся

Из каталога прогона нужно РОВНО ОДНО: последнее сообщение
`/model/iris_cam/odometry` в `bag/*.db3` — семь чисел (xyz + кватернион). Ни
видео, ни `.env`, ни остальные топики. Поэтому после `spawn_save.py` сам прогон
(десятки ГБ) можно удалять — точка уже сохранена.

Пресет `docker/sim/output/spawn/<имя>`:

```
# точка старта «among_trees»
# из прогона: .../joystick/lv1_joy_20260824_140447
# снято: 2026-08-24 (последняя поза /model/iris_cam/odometry)
# место: x=-44.907 y=-31.536 z=0.245 м, курс -15.14° (ENU: 0 = нос на восток)
# покой на хвосте записи: сдвиг 0.000 м
# формат: x y z roll pitch yaw (метры/радианы, оси мира Gazebo)
-44.9074 -31.5355 0.2450 0.0000 0.0000 -0.26422
```

`roll/pitch` зануляются (`--keep-rp` — оставить как было), `--dz N` — добавка к
высоте. Имя разрешает `scripts/sim_up.sh`: если в `SPAWN_POSE` не шесть чисел —
ищет `/root/output/spawn/<имя>` (это тот же каталог, смонтирован в контейнер) и
подставляет позу в `<pose>` модели `iris_cam` в КОПИИ мира в `/tmp`
(репозиторный SDF чист). Env применяется при СОЗДАНИИ контейнера → только
`fresh-start`; `capture_scene.sh`/`freefly_lv.sh` делают его сами.

## Грабли

- ⚠️ **Нужен ветер** (`WIND_SPD ≠ 0`, дефолт `freefly_lv.sh` — 5). Трения о землю
  в связке Gazebo+dartsim фактически нет, своего сопротивления воздуха у модели
  тоже нет — единственное демпфирование даёт плагин `WindEffects`. При
  `WIND_SPD=0` борт получает при подключении SITL толчок ~0.06 м/с и едет ВЕЧНО
  (13 м за 4 мин), причём и со ШТАТНОГО спавна в начале координат. С ветром обе
  конфигурации стоят намертво (замер 2026-08-24: поза бит-в-бит 48 с).
- Пресеты лежат в `docker/sim/output/`, а он **в `.gitignore`** — точки локальные,
  на другой бокс не переезжают. Нужен перенос — копировать каталог руками.
- Истинная поза Gazebo в таком прогоне начинается НЕ с нуля: скриптам разбора,
  которые считают старт началом координат, скармливать ту же `SPAWN_POSE`.
  Полётнику сдвиг безразличен — home/origin EKF ставится на буте от своей точки,
  локальные координаты снова начинаются с нуля в точке спавна.
