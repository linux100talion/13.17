# Переход в штатный LOITER-на-VINS (freefly-LV): от взлёта до латча

Как борт в симуляции доходит от холодного старта до штатного ArduPilot LOITER,
который держит позицию по EKF, накормленному чистым VINS (GPS к этому моменту
убит). Документ описывает ФАКТИЧЕСКУЮ механику по коду и доказанным полётам
(серия LV + пилотные freefly-LV №1-№8, 2026-08-19…21). Команда запуска:

```bash
bash src/lab/freefly_lv.sh          # LV=1: полный freefly-LV (см. src/lab/CLAUDE.md)
```

## Два контура удержания — и кто когда рулит

В одном полёте живут ДВА независимых контура позиции; между ними переключает
тумблер CH6 пульта:

| CH6 | Контур | Кто считает позицию | Кто рулит |
|---|---|---|---|
| **вверх** | «наш стек» | сырой VINS (в обход полётника) | наши демпферы/VinsHold → RC override; FCU в ALT_HOLD думает, что это стики пилота |
| **центр** | штатный LOITER | EKF полётника (EK3 на extnav = поза VINS через ray_tracer) | контроллер позиции самого FCU; наши «стики» для него — уставки скорости |
| **вниз (+1)** | MANUAL | — | сырые стики (safety-seize, всегда ALT_HOLD) |

Ключевое различие: «вверх» вообще не требует, чтобы полётник знал о VINS.
«Центр» требует ПОЛНОЙ цепочки vision→EKF, и весь этот документ — про то, как
она выстраивается по шагам.

## Участники

- **bootstrap_node** (`src/mission/.../bootstrap_node.py`) — миссия + ОЧЕРЕДЬ
  параметров FCU (EK3_SRC1_*, SIM_GPS1_ENABLE): строгий порядок, каждая запись
  ждёт свой гейт-предикат.
- **ray_tracer** (`src/nav/nav_pkg/nn1/ray_tracer.py`) — единственный мост
  VINS→полётник: публикует позу в `/mavros/vision_pose/pose` и ЯКОРИТ кадр
  VINS на кадр EKF (см. фазу 4).
- **VinsHandover / VinsHold** (`src/control/...`) — контур «тумблер вверх».
- **Freefly-шаг** (`src/mission/.../plan/step.py`) — селектор CH6 и гейт
  входа в LOITER.
- **EK3 (ArduPilot)** — потребитель: фьюзит vision-позу, когда источник
  POSXY=6 (ExternalNav) и измерения проходят инновационный гейт (~1-2 м).

## Хронология полёта (фазы и переключения)

Числа — из эталонного профиля (`BS_VINS_MIN=300`, freefly без спокойных фаз):
зрелость `ripe_n = max(600, 2×300) = 600`, глушение `kill_n = 750`.

```
фаза      0      1        2       3        4        5        6       7      8
        бут → warmup → арм → взлёт → VINS init → odom>300 → >600 → >750 → центр CH6
источник  │  GPS(3/3) ──────────────────────────────────────┐
EKF       │                                                 └→ POSXY=6, VELXY=0 ─→ GPS убит
наш стек  │             демпферы IPM ───────────┐
(вверх)   │                                     └→ VinsHold (hot-swap)
LOITER    закрыт ────────────────────────────────────────────────────────┘ латч
```

### Фаза 0 — бут: самовосстановление eeprom

`freefly_lv.sh` перед прогоном ставит `VISO_TYPE=1` в eeprom (pymavlink; без
него FCU выбрасывает VISION_* до EK3 — «requires position», урок LV1/994e471).
На старте ноды очередь параметров сначала ВОЗВРАЩАЕТ GPS-профиль — прошлый
LV-полёт оставил в eeprom extnav-источники и заглушенный GPS:

```
SIM_GPS1_ENABLE = 1   (голова очереди, без гейта)
EK3_SRC1_VELXY  = 3   (GPS)
EK3_SRC1_POSXY  = 3   (GPS)
```

Лог: `SIM_GPS1_ENABLE: установлен` → `EK3_SRC1_VELXY: установлен` →
`EK3_SRC1_POSXY: установлен` (первые «отказ — ретраю» — норма, MAVROS ещё
поднимается). До этих строк EKF может жить на мусоре из eeprom.

### Фаза 1 — ekf_warmup: арм заблокирован

Шаг `ekf_warmup` прижимает газ (руддер-арм ФИЗИЧЕСКИ невозможен), пока EKF не
начнёт держать позицию на GPS. Урок полёта №2: арм на 17-й секунде после бута
= EK3 не начал aiding, а В ВОЗДУХЕ aiding не стартует (урок LV4) → const_pos
весь полёт, LOITER невозможен до посадки. Лог: `ekf_warmup: EKF держит
позицию — к арму`.

### Фаза 2 — арм руддером, взлёт на демпферах

`пилот заармил — свободный полёт`. Тумблер вверх: roll/pitch держат
IPM-демпферы (DpHoldM — гасят скорость по оптическому потоку, позицию НЕ
держат), газ сырой у пилота, FCU в ALT_HOLD. Пилот взлетает и ЛЕТАЕТ — VINS
нужен параллакс для инициализации.

### Фаза 3 — VINS init + якорь кадра (ray_tracer)

Первая одометрия VINS (`Initialization finish!`). Мир VINS рождается ЗДЕСЬ —
в воздухе, куда борт улетел; кадр EKF считается от арма. ray_tracer сшивает
кадры: `offset = EKF − VINS` по живому `local_position` (лог: `кадр VINS
заякорен на EKF: offset=(…)`), и дальше СЛЕДИТ за якорем, пока EKF свеж и
засечки NN1 нет:

- расход кадров > 1 м → жёсткая подтяжка (лог: `якорь кадра подтянут (№N)`);
- меньше → мягкий дожим, τ=5 с.

Зачем слежение (урок №7): разовый латч ловит ХУДШИЙ момент — юный VIO врёт
масштабом до ×10 первые ~20 с (урок №3), при активном пилотировании в ветре
кадры разошлись на 4 м за 8 с ПОСЛЕ идеального латча → свап на extnav получил
vision за инновационным гейтом → «variance: position lost» ещё при живом GPS.
После свапа EKF сам следует vision → расход ≈ инновация (дециметры), слежение
затухает само. Полёт №8: одна подтяжка (1.20 м на юном транзиенте), дельта
VISP↔XKF1 0.0-0.2 м весь полёт.

С этого момента ray_tracer публикует `VINS+offset` в `/mavros/vision_pose/pose`
непрерывно — но EKF её пока ИГНОРИРУЕТ (источник ещё GPS).

### Фаза 4 — odom>300: хэндовер нашего стека (только «вверх»)

`✅ VINS сошёлся → Flow→Vins (hot-swap)` — VinsHandover снимает демпферы с
roll/pitch и ставит VinsHold (позиционный PID по сырому VINS, стики двигают
точку). Это контур «тумблер вверх», к LOITER отношения не имеет — но с этого
момента борт УЖЕ держит позицию без GPS (по-нашему). `BS_VINS_MIN=300`, а не
дефолтные 40 — свап на VINS моложе ~2 с посреди манёвра = разгон (урок LV6).

### Фаза 5 — odom>600: EKF пересаживается на VINS (при живом GPS)

Гейт зрелости `ripe_n=600` (юный VIO честен к ~21 с ≈ 550-600 odom, урок №3;
в планах со спокойной фазой hover/loiter порог 50 + гейт фазы). Очередь ставит
пару:

```
EK3_SRC1_VELXY = 0   (скорость EKF выводит сам из позы; IPM-скорость НЕ
                      фьюзится — в ветре она фантомит 1.5-2.6 м/с, урок №5)
EK3_SRC1_POSXY = 6   (ExternalNav: поза VINS от ray_tracer)
```

Лог: `EK3_SRC1_VELXY: установлен` → `EK3_SRC1_POSXY: установлен`. EKF теперь
ведётся чистой позой VINS — GPS ещё жив и страхует: если фьюжн развалится,
`local_position` протухнет и следующая фаза не наступит (безопасная
деградация). После этой пары `extnav_ready=True` — гейт LOITER открыт.

### Фаза 6 — odom>750: глушение GPS

Гейт: `odom > 750` И в воздухе (`rel_alt > 1.5`) И `local_position` свежа
(<2 с — EKF реально держит позицию на extnav). Лог: `SIM_GPS1_ENABLE:
установлен` (=0). С этого момента позиция борта — ТОЛЬКО VINS→EKF. Глушить на
земле нельзя (VINS без параллакса не инитится, урок 2026-08-19); если VINS не
ожил — GPS остаётся жить (миссия деградирует на GPS, не падает).

### Фаза 7 — центр CH6: вход в LOITER

Freefly-шаг на центре проверяет гейт (тот же, что у скриптового `LoiterHold`):

```
extnav_ready         — очередь EK3_SRC1_* пройдена (фаза 5 состоялась)
VINS свеж            — возраст одометрии < 2 с
в воздухе            — rel_alt > 1.5 м
```

- Гейт открыт → `селектор-центр: ШТАТНЫЙ LOITER — позицию держит FCU
  (extnav), стики = уставки скорости` → `set_mode LOITER` с ре-ассертом раз в
  2 с. Обычно латчится с ПЕРВОГО-ВТОРОГО захода (полёты №6, №8: один WARN
  `режим=ALT_HOLD ≠ LOITER — ре-ассерт` — это просто окно проверки).
- Гейт закрыт (щёлкнул центр рано) → `селектор-центр: LOITER не готов
  (extnav_ready=False, odom=…) — чистый ALT_HOLD`. Это НЕ ошибка: борт честно
  в ALT_HOLD (стики = наклоны), и как только фазы 5-6 доедут, LOITER возьмётся
  САМ без перещёлкивания (полёт №8: центр на odom=531 → латч через 9 с).
- Гейт открыт, но FCU отказывает >5 с → одноразовый WARN `LOITER: FCU не
  латчит режим (requires position?) — ФАКТИЧЕСКИ чистый ALT_HOLD…` — значит,
  EKF без позиции (см. «слои отказов» ниже); ре-ассерт продолжается.

### Фаза 8 — жизнь в LOITER и выходы

- **Стики в LOITER** — уставки СКОРОСТИ для контроллера FCU (не наклоны!);
  отпустил — FCU держит точку по EKF.
- **Выход по свежести**: VINS/extnav протух (возраст > 3×2 с = 6 с,
  гистерезис — мигание у порога не дёргает режим) → откат в ALT_HOLD с WARN.
- **Тумблер вверх** → наш стек (VinsHold), мгновенно.
- **Тумблер вниз (+1)** → MANUAL: всегда ALT_HOLD, «стик = наклон» —
  предсказуемая семантика для перехвата.
- **FCU сам ушёл в LAND** (EKF-failsafe) → УВАЖАЕМ, не ре-ассертим (война
  ре-ассерта с failsafe — урок №5); пилот забирает борт тумблером вверх/вниз.

## Шпаргалка пилота

1. Запусти `bash src/lab/freefly_lv.sh`, дождись `борт у пилота — арм руддером`.
2. Арм руддером (газ вниз + yaw вправо), тумблер ВВЕРХ, взлетай и летай —
   VINS нужен параллакс.
3. Следи за логом: `✅ VINS сошёлся` → `EK3_SRC1_POSXY: установлен` →
   `SIM_GPS1_ENABLE: установлен`. После этого центр CH6 латчится мгновенно.
   Щёлкнешь раньше — не страшно: повисишь в ALT_HOLD, LOITER возьмётся сам.
4. В LOITER стики = скорость; отпустил — держит. Вверх = наш стек, вниз = MANUAL.
5. Посадка и дизарм — руками пилота (freefly не сажает сам). Дизарм завершает
   миссию.

## Слои отказов, вскрытые серией (если «не держит» — проверять сверху вниз)

| № | Симптом | Причина | Фикс |
|---|---|---|---|
| LV1 | Loiter failed: requires position при живом фиде | VISO_TYPE=0 в eeprom (eeprom сильнее .parm) | 994e471 + `sitl_lv_profile.py` |
| №2 | odom=0 весь полёт | feature_tracker умер на кадре холодного старта v4l2 | try/catch (форк 4c826bd) + пересборка в nav_up (ef8d241) |
| пилотный №1 | const_pos, LOITER refused | арм до старта aiding EKF | ekf_warmup во freefly (fd8e07c) |
| №3 | position lost через 3 с после глушения | EKF-свап на юном VINS (odom>50) | ripe_n=600, kill_n=750 (77d5e39) |
| №4 | position lost ещё при живом GPS | кадры VINS/EKF не сшиты (офсет 9.6 м) | якорь кадра в ray_tracer (cd26d22) |
| №5 | циклы EKF Failsafe → LAND | фантомная скорость IPM в ветре (VELXY=6) | extern-профиль: VELXY=0 (718f019) |
| №7 | position lost при живом GPS, якорь был | разовый якорь + юный дрейф (4 м за 8 с) | СЛЕДЯЩИЙ якорь (подтяжка >1 м, дожим τ=5 с) |

Диагностика по dataflash (`/root/sitl_state/logs/*.BIN`, pymavlink DFReader):
MSG (отказы/failsafe) → дельта VISP↔XKF1 (сшивка кадров) → XKF3-инновации
(число уникальных значений: замёрзли = фьюжн голодает) → XKF4 SV/SP
(варианс-ратио, порог failsafe ~1.0).
